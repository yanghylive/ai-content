Agent 操作驾驶台产品需求文档

本文定义 /agent-console 升级为多用途 Agent 操作驾驶台的产品目标、角色、场景、功能需求、状态规则和不做范围。返回 立项书目录。

1. 产品定位

Agent 操作驾驶台是 KaypalAI 内容创作平台的桌面 Agent 主入口。它采用 ChatGPT 桌面版式对话 + 右侧当前任务工作区，让用户在同一个界面里发起任务、查看预览、确认风险、获得证据和产物。

一句话原则：Chat 负责理解意图，右侧 Canvas 负责承载当前任务的可操作工作区和交付物。它不是全局状态看板。

2. 用户角色

角色目标关注点
内容运营人员快速生成内容、处理评论、发布内容。不想理解复杂自动化配置，只想知道下一步要确认什么。
商家/店长让 Agent 执行日常后台任务。账号安全、误发风险、执行证据。
实施/客服人员远程排查、账号检查、证据导出。失败原因、权限状态、操作台账。
系统管理员管控权限、审计自动化动作。高风险动作不可绕过审批。

3. 核心场景

普通 Chat

低风险

问答、写作、总结、策略建议，不创建本机任务。

本机电脑控制

中风险

打开应用、浏览器、整理文件、读取页面，需要预检环境。

业务自动化

需治理

评论回复、发布内容、远程检查、账号检查，必须有证据和确认。

4. 功能需求

ID需求说明优先级

PRD-02意图识别识别普通问答、内容生成、本地操作、浏览器任务、文件任务、发布任务。P0
PRD-03任务草稿把指令拆成任务类型、执行范围、目标平台、账号需求、步骤、风险、确认点。P0
PRD-04预检补齐缺目标平台、账号、本机引擎、权限时给出可点击补齐动作。P0
PRD-05当前任务工作区持续显示当前任务的草稿、操作预览、步骤、确认卡、证据卡和结果产物。P0
PRD-06确认治理发布、发送、删除、改文件、账号敏感动作必须进入待我确认。P0

PRD-10旧流程兼容保留原指令台创建任务能力，不破坏商业验收脚本。P0

5. 状态规则

状态用户可见文案允许动作
chat_idle可直接输入问题或任务发送消息、上传文件、选择模式
drafting正在生成任务草稿取消、编辑输入
blocked需要补齐执行条件选择平台、选择账号、打开系统状态
ready_to_run任务已准备好创建任务、修改草稿
runningAgent 正在执行暂停、停止、查看证据
waiting_confirmation等待你确认确认执行、拒绝、查看风险
completed任务已完成导出证据、打开结果、继续任务
failed任务失败查看失败原因、重试、导出证据

5.1 右侧 Canvas 边界

右侧 Canvas 不展示全局任务数量、全局待确认数量、全局证据总数等后台看板信息。这些能力已有 /local-engine、/confirmations、任务记录和证据页承载。

右侧只回答当前对话里的问题：我现在让 Agent 做的这件事是什么、生成了什么、卡在哪里、要我确认什么、最后交付了什么。

6. 不做范围

  • 首期不做任意代码生成、任意 MCP App 生成、E2B 沙箱运行。
  • 首期不替换现有本地引擎，只做驾驶台层聚合和数据合同扩展。
  • 首期不绕过 /confirmations、商业权限、账号权限和证据留存。
  • 首期不把右侧 Canvas 做成全局监控面板；全局状态只作为后台信号和必要提示。
