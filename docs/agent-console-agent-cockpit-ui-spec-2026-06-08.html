2. 关键区域

区域职责主要组件设计要求
左栏ChatGPT 桌面版式入口当前会话、消息、输入框、快捷建议让用户先说目标，不要求先理解后台状态。
中区对话和任务形成消息、Surface、任务草稿、输入框Chat 是入口，但真实动作必须转成结构化任务。
右栏当前任务工作区任务草稿、浏览器/文件/发布预览、确认卡、证据卡、交付物像 Codex 右侧一样展示当前任务正在产生和操作的东西，不做全局监控。
顶部轻量环境提示必要的登录/引擎/权限异常提示只在影响当前任务时出现，不常驻展示全局统计。

3. 响应式规则

断点布局规则
桌面 ≥ 1200px双主区左侧 Chat 入口 + 右侧 Persistent Canvas；右侧宽度优先保证预览/产物可读。
平板 768-1199px双栏/可收起Chat 与 Canvas 并排；Canvas 可全屏查看当前任务产物。
手机 < 768px单栏 TabsChat、工作区、证据/确认三个 Tab，输入框固定底部。

4.1 禁止主内容

  • 不把右侧 Canvas 做成“本机引擎在线、运行中数量、待确认数量、证据总数”的仪表盘。
  • 不重复 /local-engine、/confirmations、任务记录、证据库已有能力。
  • 全局状态只能作为当前任务的阻断原因、补齐动作或跳转入口出现。

4. 状态视觉

阻断状态

使用黄/琥珀色边框，给出原因、影响和一个主补齐动作。

高风险确认

使用红色风险标识，必须展示目标、动作、账号、后果和确认按钮。

完成状态

使用绿色状态，展示结果、证据数量、打开结果和导出证据。

5. 交互原则

  • 能用按钮补齐的条件，不让用户重新写提示词。
  • 真实动作必须在任务草稿里可见，不能隐藏在 AI 文本里。
  • 确认动作要展示后果，不只展示“确认/拒绝”。
  • 证据和失败原因要靠近当前任务，不只放在独立记录页。
  • 按钮文字使用真实动作，例如“选择抖音账号”“创建浏览器任务”“导出证据”。
