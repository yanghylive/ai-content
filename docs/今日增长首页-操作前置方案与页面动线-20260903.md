# 今日增长首页 · 操作前置方案与页面动线定稿

> 定稿：2026-09-03（多轮用户反馈收敛）· 适用：`frontend/src/app/(dashboard)/today/today-center.tsx`
> 配套：文件头版式规范注释同步（today-center.tsx 顶部）与本文档一致。

---

## 一、问题

首页曾把「增长功能」（本页唯一需要用户点击去办事的入口矩阵）排在数据长尾末端：
页头 → 告警 → AI 简报 → 漏斗 → 价值账单 → 增长功能 → 最近运行。
用户到达操作区前需滚过多屏被动阅读内容；「AI 价值账单」等价值证明类阅读内容反而占据操作位附近的视觉权重。

## 二、方案逻辑（操作前置）

**原则**：首页动线按「用户任务顺序」而非「组件开发顺序」组织——先让用户知道今天如何、有没有风险，然后立刻能「去办事」，再向下展开叙事与数据细节。

1. 页头 = 一眼看今天（统计卡 + 趋势主图）
2. 风险 = 先处理告警（需要关注的事项）
3. **操作 = 增长功能紧跟告警**（唯一动作资产，不埋在数据长尾）
4. 叙事 = AI 简报一句话交代 AI 在干什么
5. 数据细节 = 漏斗 → 价值账单（同源衍生、被动阅读）
6. 日志 = 最近运行收尾

**增长功能自身分层**：与今日数据直接相关的枢纽（线索池 / 获客任务 / 账号健康，带今日角标）渲染为 3 列 hero 大卡；其余四个常用功能（获客策略 / 增长工作流 / 增长复盘 / RPA 工作台）4 列标准主卡，无孤卡。标题下注明「与今天数据直接相关的功能在最上面」。

## 三、最终页面动线（自上而下，2026-09-03 定稿）

```text
1  页头：标题 + 刷新/新建获客任务 + 5 统计卡（概览，一屏内）
2  需要关注的事项（风险告警，无则不渲染）
3  增长功能（3 hero + 4 standard 操作入口）—— 首屏内可见（实测 1440px 顶 ~659px）
4  近 7 日趋势主图（从页头区下移让位，数据细节）
5  今日 AI 简报
6  转化漏斗
7  AI 价值账单
8  最近运行（日志收尾）
```

**关键决策**：趋势主图原本紧跟统计卡（占 ~280px 将增长功能挤出首屏）。为让操作区最大化上提，
将其移至增长功能之后——打开页面无需滚动即可看到操作入口。增长功能 = 本页唯一页面级大标题（28px）+ 主色渐变操作卡。

| 项 | 位置 |

## 五、验收（浏览器实测 1440px）

- 区块顺序与第三节完全一致（getBoundingClientRect top 排序断言）
- 增长功能 7 个入口齐全；hero 行 3 卡带角标（有数据时）
- 无 console.error；明/暗主题切换正常
- 边界：overview 失败 → 简报/价值账单隐藏但增长功能仍渲染（无角标）

## 六、功能卡「操作语言」（2026-09-03 二轮反馈补定）

**反馈**：功能卡与数据卡长得一样（同白框同浅紫），用户分不清「展示」与「操作」；即使分层视觉权重仍不足。

**定稿设计语言——数据卡与操作卡两套视觉**：

| 维度 | 数据卡（统计/漏斗/账单/最近运行） | 操作卡（增长功能，唯一主色渐变处） |
|---|---|---|
| 图标 | 无 / 16px 小标 | hero 52px、standard 44px 主色渐变实底白图标（内联 style 定尺寸） |
| 卡形态 | 白框灰字 kaypal-v3-panel | 白纸底 + 主色描边（accent-border），hover 主色加深 + 上浮阴影 |
| 标题 | 常规 14/600 | hero 15px bold、standard 14/600（hero 用内联 style 抗 .kx-view h3 全局覆盖） |
| 悬停 | 边框微变 | 图标 scale-105、箭头位移、主色边加强 |
| 区块载体 | 白面板 | paper-muted 底面板，副文案为动作引导「去处理线索、任务与账号，点卡片直接进入」 |

**坑位记录**：
- Tailwind3 默认档位不含 `h-13/w-13`（52px），写成类会整类失效致图标块坍缩为 20px —— 一律用内联 style 定图标块尺寸；
- `.kx-view h3` 全局规则（font-size 固定）会覆盖 `text-[15px]`/text-base 工具类 —— hero 标题字号用内联 style 保证。

**验收**（浏览器实测 1440px，已完成）：7 卡齐全；hero 图标 52×52 渐变实底、标题 15px bold、卡片主色描边、区块 paper-muted 底；console 零错误。

### 六A. 标题外置尝试与撤销（2026-09-03 记录，防回归）

曾尝试将全部数据区块标题（趋势/漏斗/简报/账单/最近运行）外置为 28px 大标题——
**用户反馈不好看：太占地方、分不清主次，已整体撤销**。恢复规则：
- 数据区块标题一律在卡片内（text-base，实际 15px 由 `.kx-view h2` 决定）；
- 仅「增长功能」区块标题外置 28px（内联 `SECTION_TITLE_TEXT`）——作为唯一页面级大标题突出操作区；
- 版式注释已同步，勿再全区块外置。

### 六B. 操作区上提首屏（2026-09-03 定稿）

**反馈**：增长功能仍要靠下，用户不易察觉可点与重要。
**方案**：趋势主图从页头区移出（在增长功能之后渲染），增长功能紧跟风险卡上提——
实测首屏内可见（增长功能标题顶 ~659px < 900px 视口）。动线见第三节。
