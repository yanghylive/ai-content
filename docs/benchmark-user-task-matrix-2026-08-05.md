# 用户任务链路对比矩阵

日期：2026-08-05  
方法：用户任务链路法  
用途：实现前冻结范围；不以页面存在、接口存在或任务记录存在代替外部结果。

## 判定说明

- `已具备结构`：源码和接口显示有实现，但没有 A 级真实证据。
- `部分闭环`：能完成一段链路，仍有关键步骤需要人工或缺少回读。
- `明确缺口`：当前代码明确不支持，或存在阻断条件。
- `待真人验证`：工程结构可能存在，但需要真实账号、真实平台或 Windows 真机。
- 参考产品列只记录用户可观察能力和静态材料，不用于复制其代码或资源。

## 关键结论

### 参考产品真正领先的部分

不是页面数量，而是“本地执行器直接完成外部动作”的密度：Windows 本地服务、社交平台互动、微信联系人/群/朋友圈和任务执行组合在一个本地运行时内。静态材料能证明其功能范围，但不能单独证明长期稳定性。

### JIUZHANG 真正领先的部分

是更宽的产品基础设施：多平台发布适配、租户、计费、额度、审计、内容和移动端框架。当前风险在于这些基础设施和真实外部动作之间的回读、授权、幂等和故障恢复还没有全部形成 A 级证据。

### 不能混为一谈的差距

- “有发布 API”不等于“真实发布完成”。
- “弹窗显示绑定”不等于“账号列表、任务和发布器使用同一账号状态”。
- “有互动接口”不等于“已支持 Windows 微信自动化”。
- “有租户字段”不等于“已经通过生产级跨租户隔离回归”。

## 实现前冻结的 P0

1. Windows 安装、启动、升级、失败诊断和回滚。
2. 账号绑定、刷新、登录失效和视频号列表同步。
3. 内容到真实发布、外部结果回读和失败重试。
4. 互动任务的授权、目标确认、执行、回读和审计。
5. 云端额度/冻结状态和本地执行授权的一致性。

其余能力不得用新增页面入口掩盖上述链路缺口。
