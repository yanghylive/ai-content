# 移动端商用能力补齐方案（Android 壳原生模块扩展）

> 2026-08-10 · 基于现有 Android WebView 壳（mobile/，约 1000 行手写原生）· 面向商用移动端能力补齐

---

## 一、结论先行：不迁 Capacitor，现有壳补原生模块

现状壳已具备的（无需重复开发）：
- `JsBridge.kt`（161 行）：shareText 系统分享 / openApp 深链调起（抖音等）/ 剪贴板 / 语音 ASR / getInstalledApps
- `MainActivity.kt`（360 行）：19 项 WebView 适配（返回键三层 / 下拉刷新 / 进度条 / 安全区 / 主题联动 / 断网页）
- `AgentService.kt`（235 行）+ `RpaAccessibilityService.kt`（244 行）：agent 前台服务 + 无障碍 RPA（Capacitor 无现成插件，迁移必须自写）

**Capacitor 迁移成本 = 1000 行原生重写 + 19 项适配回归测试，收益仅在「上 Google Play + 未来出 iOS」时才成立。** 国内 Android 商用场景，现有壳补模块是正解。

## 三、各能力详细方案

### 1. 生物识别登录（无外部依赖，最快落地）

- **原生**：`MainActivity` 增加 `BiometricPrompt`（Android 10+ 推荐），`JsBridge` 增加 `biometricAuth(reason)` 方法
- **流程**：H5 登录页点击「指纹/面容解锁」→ `window.JiuZhang.biometricAuth("验证身份")` → 系统弹窗 → 成功后回传 `{"ok":true}` → H5 携带已登录态 token 续期或完成解锁
- **注意**：仅作为"已登录态下的快速解锁"，不替代首次密码登录（密钥存储用 `EncryptedSharedPreferences` 或 Keystore）
- **权限**：`USE_BIOMETRIC`（Manifest 声明）

### 2. 系统文件访问（无外部依赖）

- **原生**：`JsBridge` 增加 `pickFile(mimeType)`（`ACTION_OPEN_DOCUMENT`）与 `saveFile(content, name, mime)`（`ACTION_CREATE_DOCUMENT`），`onActivityResult` 取 URI 后转流
- **H5 侧**：素材采集页「从本机选择文件」、导出页「保存到本机」接桥
- **SAF 优势**：无需存储权限（Android 10+ 分区存储兼容）

### 3. 本机号码一键登录（阿里云号码认证服务）

**选型理由**：一个 SDK 覆盖移动/联通/电信三网；已通过泰尔实验室 SDK 安全检测（商用合规加分）；按量计费（取号成功才计费）。

**申请流程（SDK 申请指南）**：
1. 注册阿里云账号 → **企业实名认证**（前置条件，需营业执照）
2. 控制台搜索「号码认证服务」→ 立即开通（预充值，按量付费）
3. **创建认证方案**：填写方案名称、APP 名称、操作系统（Android）、**包名 + 应用签名**
   - 签名获取：`keytool -list -v -keystore <release.jks>` 取 SHA1/SHA256，或对已签名 APK：`keytool -printcert -jarfile <app.apk>`
4. 下载客户端 SDK（号码认证 SDK Android 版）+ 获取方案号（SchemeCode）与 AppKey/AppSecret
5. 服务端开通 OpenAPI 权限（Dypnsapi）

**技术流程**：
- 客户端：SDK 初始化 → 唤起授权页（SDK 内置 UI）→ 用户同意 → `getLoginToken()` 拿到 token（有效期：移动 2min / 联通 60min / 电信 10min，单次有效）
- 服务端：`GetMobile` API + token → 返回明文手机号（11 位）
- 业务侧：手机号查用户 → 有账号直接建会话；无账号自动注册（或引导绑定）

**后端接口**（新增）：`POST /api/auth/phone-login { token }` → 校验取号 → 建会话，返回与现有 login 相同的 `{user, expiresAt}` + Set-Cookie。

### 4 & 5. 微信分享 + App 内微信登录（微信开放平台 SDK）

**申请流程（SDK 申请指南）**：
1. 注册微信开放平台账号（open.weixin.qq.com）——需**未绑定微信私人账号的全新邮箱**、企业名称、营业执照注册号、支付 300 元认证费（管理员姓名/身份证/手机号；期间会有审核电话沟通）
2. 完成「开发者资质认证」（300 元，微信登录功能默认随之开通）
3. **创建移动应用**：
   - 基础资料：应用名称/简介/Logo（28×28 与 108×108 两张）/官网/运行流程图（10 张内）
   - Android 平台：**应用包名**（`com.aicontent.desktop.mobile`）+ **应用签名**（MD5，用微信官方「签名生成工具」APK 安装到手机输入包名获取，或 keytool 计算）
4. 提交审核，1-7 个工作日（一般 1 天左右过）
5. 审核通过后在「管理中心」获取 **AppID + AppSecret**（注意：**签名必须与发布包一致**，debug 签名和 release 签名不同会导致调不起微信）

**集成**：
- Gradle 引入 `com.tencent.mm.opensdk:wechat-sdk-android`（最新版）
- 登录：`sendReq( SendAuth.Req(scope="snsapi_userinfo") )` → 回调 code → 后端新增 `POST /api/auth/wechat-app-login { code }` → 微信 API 换 access_token/userinfo → 建会话（复用现有 `handleWechatCallback` 的建会话逻辑）
- 分享：`SendMessageToWX.Req`（好友 `SceneSession` / 朋友圈 `SceneTimeline`）；**视频号分享**属微信生态，走同 SDK 的开放能力

**合规提醒**：微信开放平台**禁止诱导分享朋友圈**；分享文案不得含诱导性话术。

### 6. 抖音分享

- **现状已够用**：`openApp("snssdk1128://")` 或包名调起抖音，配合剪贴板复制文案/链接，用户粘贴发布
- **发布级能力**：需抖音开放平台企业资质 + 移动应用审核（AppID + 签名绑定），走「视频上传」能力——仅当需要"App 内直接发布到抖音"时才申请

### 7. 推送通知（最大项，1-2 周）

**选型**：国内 Google FCM 不可用 → **厂商通道 + 聚合推送**。

**厂商通道申请要求（SDK 申请指南）**：

| 厂商 | 账号类型 | 是否需上架 | 参数 | 备注 |
|------|---------|-----------|------|------|
| 小米 | 企业开发者 | ✅ 需要上架小米商店 | AppID/AppKey/AppSecret | 个人账号无推送权限 |
| 华为 | 个人/企业均可 | ❌ 不需上架（上传 APK 即可）| AppID/ClientID/ClientSecret | 最宽松 |
| OPPO | 企业开发者 | ✅ 需要上架 OPPO 商店 | AppID/AppKey/AppSecret/MasterSecret | 未上架仅测试 1000 条/天 |
| vivo | 企业开发者 | ✅ 需要上架 | AppID/AppKey/AppSecret | 仅支持企业 |
| 荣耀 | 企业开发者 | ❌ 不需上架 | AppID/AppSecret/ClientID | 需证书指纹 |

**推荐路线**：
- 若想省去四家厂商分别接入的工作 → 用**聚合推送**（极光 JPush / 个推 / 腾讯云移动推送 TMF），一次接入、自动适配各厂商通道
- 若只要华为（当前测试主力）+ 小米，可直接分别接

**技术要点**：
- Manifest 已有 `POST_NOTIFICATIONS` 权限（Android 13+ 需运行时申请）
- 通知点击深链：payload 带 `path`（如 `/tasks/confirmations`），通知点击 → 壳拦截 intent → `webView.loadUrl(base + path)` 直达页面
- 后端已有 `push_subscriptions` 表（Web Push 基础），可扩展同表存 deviceToken 或新建 `mobile_devices` 表（现有 `mobile_devices` 表已存在，可复用）
- 推送场景：审批待办 / 发布结果回读 / 监控告警 / 额度预警

### 8 & 9. 辅助权限（已有）与上商店

- 辅助权限：✅ 已具备
- 上商店（正式分发）：
  1. **正式签名**：生成 release keystore（`keytool -genkey`），`versionCode` 递增，`versionName` 升版；⚠️ 签名证书一旦换，微信/厂商通道绑定全部失效
  2. **隐私合规**：隐私政策 URL + 权限说明页（收集手机号/录音/辅助权限的目的）
  3. **备案/软著**：国内商店需软件著作权证书、ICP 备案；Google Play 需开发者账号（$25）+ 目标 API 合规（targetSdk 35 已达标）

## 四、后端新增接口清单

| 接口 | 说明 |
|------|------|
| `POST /api/auth/phone-login` | 号码认证 token → 换手机号 → 建会话/自动注册 |
| `POST /api/auth/wechat-app-login` | 微信 App code → 换用户 → 建会话（复用 handleWechatCallback）|
| `POST /api/push/register` | 客户端注册 deviceToken（厂商通道/聚合返回的 token）|
| `POST /api/push/unregister` | 注销 |
| `POST /api/push/send`（内部）| 后端事件（审批/发布/告警）触发推送 |

## 五、分阶段实施计划

### 阶段 A · 无外部依赖（立即开工，3-4 天）

6. 厂商推送：小米/华为申请（OPPO/vivo 需上架，视商店计划）

### 阶段 C · 商店上架（流程驱动）
7. 正式签名（**先于一切绑定类 SDK 申请**——微信/厂商通道绑定的是签名）
8. 隐私政策 + 权限说明
9. 软著/备案 → 提审

## 六、风险与合规清单

- ⚠️ **签名一致性**：正式 keystore 必须先确定，微信 AppID、厂商通道、号码认证方案绑定的都是"包名+签名"，中途换签名全部失效
- ⚠️ 微信禁止诱导分享朋友圈；推送频率过高会被厂商限流/下架
- ⚠️ 手机号/录音/辅助权限属敏感权限，隐私政策必须逐项说明用途
- ⚠️ 聚合推送 vs 直连厂商：聚合省接入但多一层依赖和费用；直连可控但四家都要维护
- ⚠️ 号码认证仅支持 SDK 方式（运营商要求），H5/网页场景不可用，只能 App 内
