# AgentWaker 双渠道真机验收清单

这份清单只覆盖本地代码无法替代的真实账号、真实平台和真实浏览器验证。所有步骤都使用测试账号、测试素材和小范围目标；禁止直接使用生产公众号群发或小红书主账号。

## 0. 验收前置

- [x] 3010 前端可访问：`http://127.0.0.1:3010`
- [x] 3011 后端健康：`/api/health`、`/api/health/ready` 与 `/api/auto-upload/health` 均为 `ok`
- [ ] 登录测试账号已绑定明确工作区；页面不再出现“请选择组织”或 401
- [ ] 公众号测试号已准备 AppID、Access Token、默认封面 `media_id`
- [ ] 公众号服务端 IP 白名单已包含当前出口 IP
- [ ] 在 `/platforms` 新增 JPage 授权，Token 已加密保存，服务地址为允许的 HTTPS 域名，默认可见性为 private
- [ ] 小红书测试账号已在受控浏览器或官方测试入口登录
- [ ] 测试素材均为自有或获授权素材，正文来源链接可公开访问
- [ ] 已确认“保存草稿”和“正式发布”是两个独立动作
- [ ] 已确认测试期间不会开启群发、定时发布或大规模互动

## 1. 小红书运营助理

### 1.1 生成与回写

- [ ] 打开 `/content/xiaohongshu-assistant`，确认角色状态为可用
- [ ] 填写品牌、受众、产品、关键词和素材来源，提交一条测试任务
- [ ] 任务从 `draft/running` 进入完成或待确认，没有重复任务
- [ ] 产物包含标题、正文、标签和 5 至 7 张卡片
- [ ] 首张卡片为封面，比例和文字在移动端不溢出
- [ ] 文章库能查到同一 `articleId`，素材库能查到对应卡图
- [ ] 刷新页面后任务、产物和失败原因仍可恢复

### 1.2 发布前审批

- [ ] 待确认页展示内容检查、卡图检查和账号写入检查
- [ ] 未勾选必选检查项时，确认按钮不可提交
- [ ] 执行前只生成发布准备，不发生账号写入
- [ ] 切换到另一条任务后，旧任务的 loading、错误和产物不会串入新任务
- [ ] 连续双击执行或快速刷新不会创建第二个 run

### 1.3 测试账号发布与回读

- [ ] 仅在确认准确载荷后发布一条测试笔记
- [ ] 发布后回读平台笔记 ID、标题、正文摘要、发布时间和账号标识
- [ ] 3010 发布记录与平台回读 ID 一致
- [ ] 使用同一任务重复提交时被幂等保护，不产生第二条笔记
- [ ] 发布失败时页面显示明确失败原因，并可安全重试或进入人工处理

## 2. 公众号运营助理

### 2.1 文章、HTML 和私有预览

- [ ] 打开 `/content/wechat-official-assistant`，确认角色状态为可用
- [ ] 生成一篇包含来源账本的测试文章
- [ ] 检查标题、摘要、作者、正文、来源链接和 HTML 结构
- [ ] 移动预览无横向滚动、无脚本、无事件属性和危险链接
- [ ] 上传同一版本 Markdown 与 HTML 到 JPage，确认两者哈希与本地版本一致
- [ ] JPage 两份文件都为 private，读回内容与本地一致
- [ ] 分别打开已认证的 Markdown 与 HTML 位置，在 375 px 和 390 px 宽度检查图片、标题、代码和正文
- [ ] 完成“申请渲染确认 -> 确认远程移动预览”，页面状态变为通过
- [ ] JPage 失败时流程停在草稿前，不继续调用微信写入

### 2.2 公众号草稿

- [ ] 确认准确的公众号账号、标题、正文、来源和封面
- [ ] 通过服务端一次性确认后创建草稿
- [ ] 微信返回 `media_id`，系统保存到发布记录
- [ ] `draft/get` 回读标题和正文均匹配，记录进入 `draft_saved`
- [ ] 回读不匹配时记录不进入可发布状态，页面明确阻断正式发布
- [ ] 刷新页面或重新打开任务后，仍能看到账号、草稿状态和 `media_id`
- [ ] 草稿创建成功但回读暂时失败时，使用“回读/对账”恢复，不重复创建草稿

### 2.3 正式发布与状态回查

- [ ] 只有已验证的同账号、同文章、同正文 `media_id` 可以申请正式发布确认
- [ ] 正式发布确认显示最终标题、账号、正文版本和风险项
- [ ] 确认后提交一次测试发布，不执行群发
- [ ] 保存 `publish_id`，状态从 `publishing` 到最终状态可刷新
- [ ] 成功状态回读文章 ID、文章 URL 和发布时间
- [ ] `audit_failed`、`originality_failed`、`failed`、`deleted` 能显示为失败而非永久处理中
- [ ] 正式发布成功后文章库状态与发布记录一致
- [ ] 重复提交、换账号、换正文或篡改 `media_id` 均被阻断

## 3. 异常和恢复

- [ ] 在生成过程中刷新页面，任务可继续显示正确进度
- [ ] 在生成过程中重复点击执行，服务端只保留一个执行者
- [x] 模型请求超时会取消底层请求，选题状态可恢复（自动化已覆盖）
- [ ] 在草稿创建后断开网络，确认可通过回读恢复，不重复写草稿
- [ ] 在正式发布提交后断开网络，确认记录进入对账状态，不盲目重发
- [ ] 重启 3011 后，任务、发布记录和审批单可恢复
- [ ] 过期确认单不能继续执行，页面可重新申请确认
- [x] 不同用户、不同工作区访问文章、任务、账号和发布记录会返回 404/403（自动化已覆盖）
- [x] 删除账号需要服务端确认，删除响应不包含 Token 或配置密钥（自动化已覆盖）

## 4. 验收证据

每条通过项至少保存以下证据之一：

- 截图：包含页面 URL、任务 ID、账号名称和状态
- API 响应：脱敏后的任务、发布记录、平台回读结果
- 日志：对应时间段的 run ID、record ID、publish ID 和错误原因
- 平台截图：仅保留测试账号、测试文章和测试笔记，不包含 Token、Cookie 或个人信息

最终签字前必须记录：

- [ ] 测试时间、操作人、测试账号和工作区
- [ ] 小红书平台笔记 ID 与公众号 `media_id/publish_id/article_id`
- [ ] 失败场景和恢复结果
- [ ] 未触发群发、定时发布或非测试账号写入
- [ ] P0/P1 缺陷为 0，剩余问题有责任人和截止时间

## 5. 明确停止边界

- 任何发布前载荷发生变化，必须重新申请确认
- JPage 私有校验未通过，不进入公众号草稿写入
- 公众号回读不匹配，不进入正式发布
- 平台返回未知状态，不自动重试或群发，转人工对账
- 不把任何真实凭据、Cookie、Token、私有预览地址提交到 Git 或工单
