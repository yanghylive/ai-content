# 3010 / 3011 完整功能测试要求

版本：v1.0
适用对象：AI Content 桌面端、Web 前端 3010、后端 3011、Agent-S、本地引擎及发布安装包
测试原则：以当前可运行代码和真实证据为准，规划、接口声明、mock、截图摘要均不能单独证明功能通过。

## 1. 测试目标

本测试要求用于判断以下闭环是否真实可用：

1. 用户可以登录系统，在租户和角色权限范围内完成配置、创作、获客、互动、客户管理、审批和发布。
2. 3010 前端与 3011 后端之间的鉴权、数据、错误提示和状态流转一致。
3. 需要本地执行的任务由包内 Agent-S/本地引擎真实执行，具备可回读的结果和证据。
4. 高风险动作不会绕过审批、重复执行、误计费或误发布。
5. 失败、断线、超时、取消、重试和恢复均有明确状态，不得静默显示为空或伪装成功。
6. 发布包包含与当前源码相同的前端、后端、原生依赖、浏览器和平台引擎，安装后能独立运行。

## 2. 测试范围和边界

### 2.1 运行对象

| 对象 | 地址/入口 | 必测内容 |
|---|---|---|
| 前端 3010 | `http://127.0.0.1:3010` | 路由、表单、状态、错误、响应式、浏览器控制台 |
| 后端 3011 | `http://127.0.0.1:3011/api` | 鉴权、租户隔离、业务接口、任务状态、证据、健康检查 |
| Agent-S | `/api/agent-s/health`、`/api/agent-s/status` | 真实 runner、浏览器控制、会话、工具和证据 |
| 本地引擎 | `/api/local-engine/*` | 浏览器、平台账号、微信、本地文件、执行记录 |
| 桌面包 | `desktop/dist` 安装包 | 安装、启动、更新、资源、原生引擎、数据目录 |
| 发布服务 | OSS `latest.yml` / `latest-mac.yml` | feed、包文件、blockmap、哈希和可下载性 |

### 2.2 不在自动通过范围内的事项

- 未打开微信、未登录第三方平台、没有可用供应商凭据或没有测试账号时，只能记为环境阻塞，不能记为通过。
- 真实发布、真实私信、真实加好友、真实朋友圈/群发、连续内容生产，必须有测试账号、明确人工批准和可回读证据。
- 仅有 mock、空数组、固定假响应、兼容壳、summary 字段或接口返回 200，不能证明真实执行能力。
- 云端额度、供应商、第三方平台的外部故障要保留原始错误和重试证据，不得改判为业务成功。

## 3. 测试环境要求

### 3.1 服务和依赖

- 3010、3011 均启动，前端请求通过配置的 `/api` 或明确的 3011 API 地址访问。
- 3011 `/api/health` 返回 `ok=true`、`ready=true`。
- Agent-S 必须报告 `ok=true`、`browserControl=true`，且 `runner_mode` 为真实 node/playwright 模式，不得为 mock、summary-only 或 compatibility-shell。
- Playwright MCP 必须在线，使用与当前平台匹配的包内 Chromium；Mac 不得使用 Windows Chrome，Windows 不得使用 Darwin 引擎。
- 数据库测试必须明确模式：推荐 SQLite 隔离库；若使用 PostgreSQL，记录脱敏连接目标和迁移版本。
- 测试开始前建立独立测试租户、管理员、普通成员、无权限用户、至少两个平台账号和一组可删除的测试客户。

### 3.2 测试数据

准备以下数据并记录 ID：

| 数据 | 最低数量 | 用途 |
|---|---:|---|
| 管理员用户 | 1 | 管理配置、迁移、发布审批 |
| 普通成员 | 1 | 权限拒绝、租户隔离 |
| 第二租户用户 | 1 | 跨租户读写隔离 |
| 抖音测试账号 | 1 | 评论、私信、获客、发布 |
| 视频号测试账号 | 1 | 评论、私信和发布 |
| 微信测试账号 | 1 | 草稿、联系人、群和朋友圈受控验收 |
| 正常素材 | 图片、视频、文档各 1 | 内容生产和文件选择 |
| 损坏/超大素材 | 各 1 | 失败提示、大小和格式校验 |
| 文章/视频草稿 | 各 1 | 审批、发布、回读 |
| 测试客户/线索 | 至少 3 | CRM、批量任务、去重和跟进 |

禁止把真实客户、真实账号密码、生产数据库或生产发布目标直接用于本测试。

## 4. 测试证据要求

每条用例必须记录：

- 用例 ID、执行时间、执行人、源码 commit、包版本和测试环境。
- 操作前置、实际请求/响应摘要、页面截图或录屏、任务 ID/会话 ID。
- 对外动作的目标账号、平台、审批 ID、执行状态、回读结果和证据 ID。
- 失败时保留 HTTP 状态、错误码、用户可见文案、后端日志和重试结果。
- 证据不得包含密码、完整 token、Cookie、私钥或未脱敏个人信息。

证据必须能从任务、审批、运行记录或证据中心回查，不能只存在测试人员本地终端。

## 5. P0 冒烟测试

P0 用于每次提交、重启和发版前快速判断系统是否可继续测试。任一 P0 失败，停止后续真实执行。

| ID | 操作 | 预期 |
|---|---|---|
| P0-01 | 打开 3010 登录页并登录 | 登录成功，跳转工作台，不循环跳转 |
| P0-02 | 调用 `GET /api/health` | HTTP 200，`ok=true`、`ready=true` |
| P0-03 | 调用 Agent-S health/status | 真实 runner、浏览器控制和 MCP 状态明确 |
| P0-04 | 打开工作台、发布中心、Agent 指令台、待确认、证据产物 | 页面非白屏，核心标题和导航可见 |
| P0-05 | 创建一个只读/草稿任务 | 返回任务 ID，列表可见，状态可追踪 |
| P0-06 | 断开一次非关键请求或模拟 500 | 页面显示失败原因和重试入口，不显示无解释空列表 |
| P0-07 | 重新加载失败页面 | 请求重新发出，成功后错误提示清除，数据不重复 |
| P0-08 | 登出后访问受保护 API | HTTP 401/403，不能读到前一用户数据 |
| P0-09 | 重启 3011 | 服务恢复，数据库和测试数据不丢失，端口无重复进程 |
| P0-10 | 检查浏览器控制台和请求失败 | 不得有未解释的 5xx、未处理 Promise rejection 或持续轮询风暴 |

## 6. 认证、用户、租户和权限

### 6.1 登录和会话

- 正确用户名/密码登录成功，错误密码显示可理解的失败原因，不泄露后端堆栈。
- token/cookie 过期后，前端回到登录或显示重新登录提示；不得把 401 当空数据。
- 并发打开多个标签页时，登录、登出和刷新状态一致。
- 3010 页面、3011 API、Agent-S 会话必须绑定同一个用户和租户上下文。
- 刷新页面、关闭再打开桌面端后，允许保留的会话可恢复，禁止恢复已撤销会话。

### 6.2 角色和租户隔离

- 管理员可执行管理操作；普通成员只能执行被授权操作；未知角色默认拒绝。
- `admin`、`super_admin` 和云端超级管理员的判定口径必须与 auth guard 一致。
- 用户 A 不得读取、修改、迁移或删除租户 B 的项目、账号、客户、任务、素材、记忆和证据。
- 跨租户 ID、伪造 `userId`、修改路径参数和重放旧审批 ID 均应返回 403/404，且数据库不发生越权写入。
- owner 迁移必须记录操作者、原 owner、新 owner、审批/审计信息；失败不得部分迁移。

## 7. 配置和基础数据功能

逐页验证“新增、编辑、查看、筛选、删除/停用、刷新、失败重试、权限拒绝、空态”八类状态：

| 功能域 | 页面/入口 | 必测内容 |
|---|---|---|
| AI 模型 | `/models`、`/capabilities/models` | 模型配置、启停、默认模型、不可用模型提示、密钥不回显 |
| 应用市场 | `/apps`、应用详情 | 应用安装/启用/停用、能力说明、错误状态 |
| 选题 | `/topics` | 新增、评分、生成中回收、完成、失败、重复和分页 |
| 内容风格 | `/styles` | 新增、编辑、复制、删除、引用关系 |
| 内容模板 | `/templates` | 新增、变量校验、预览、保存、删除 |
| 内容策略 | `/strategies` | 创建、启用、停用、关联平台和失败提示 |
| 定时任务 | `/schedules` | 创建、修改、暂停、恢复、触发记录、时区和重复执行防护 |
| 平台账号 | `/platforms`、`/distribution?tab=accounts` | 登录、刷新、健康状态、过期、解绑和账号隔离 |
| 素材 | `/materials`、`/content/*` | 上传、格式/大小校验、预览、失败清理、引用和删除 |
| 知识库 | `/knowledge`、`/knowledge-base` | 新建、导入、搜索、权限、删除和索引失败 |

所有保存动作必须具备幂等或重复点击防护；失败后不能显示为成功，也不能生成不可见孤儿记录。

## 8. 内容生产和媒体功能

### 8.1 文章和工作区

- 从选题/模板生成文章，编辑器保存后刷新仍可恢复。
- 生成中、成功、失败、取消、超时状态均可见；失败原因和下一步动作明确。
- 文章预览与保存内容一致，特殊字符、图片、链接、表格和长文本不破坏布局。
- 版本记录可查看、恢复和导出，恢复操作不覆盖错误版本。

### 8.2 图片、视频和加工

- AI 图片生成、视频生成、视频下载、视频工作台、产品剪辑、换脸等入口均能创建任务并显示任务 ID。
- 输入缺失、格式错误、供应商拒绝、额度不足、网络超时分别显示可理解原因。
- 任务完成必须有真实文件或可回读 URL；只有“生成成功”文本而无产物判定失败。
- ffmpeg/ffprobe、sharp、浏览器和 Prisma 原生依赖与目标平台匹配。
- 取消任务后不继续计费、不继续写入结果；重复点击不得创建重复任务。

### 8.3 供应商缺失和降级

- 缺少可选供应商凭据时，页面显示明确的不可用原因（例如 `VENDOR_CREDENTIAL_MISSING`），不得产生无意义 503 噪音。
- 引擎网络错误、业务拒绝、凭据错误必须分类；业务拒绝不得回退到会计费的云端路径。
- 降级功能必须明确标注“不可用/降级”，不能伪装为成功。

## 9. 获客、线索和 CRM

### 9.1 获客任务

- 创建获客配置前执行预检；账号未登录、平台不支持、风险不允许时阻止执行并显示原因。
- 真实触达前必须创建一次性审批/确认编号；缺少确认编号不能执行。
- 创建后可从当前页面执行或进入列表执行，任务 ID、配置 ID、账号 ID 必须一致。
- 执行失败在就近位置展示原因和下一步，页面顶部错误与局部错误不得互相覆盖。
- 采集、评论、私信任务必须区分草稿、待审批、执行中、成功、失败、取消和待回执。

### 9.2 线索和 CRM

- 线索导入、去重、评分、标签、负责人、跟进记录和导出可回读。
- 批量跟进任务按每个目标记录状态；部分失败不能被汇总成功掩盖。
- 客户详情、线索详情、互动记录和任务证据必须在同一租户内关联，跨租户访问拒绝。
- 删除、合并、转交等破坏性操作需要确认，失败时原数据保持完整。

## 10. 发布和互动闭环

### 10.1 发布中心

- 图文发布、视频发布、发布任务、合规检查、运行日志、发布账号和素材选择均可打开。
- 发布前校验标题、正文、封面、视频、账号、平台规则和权益状态。
- 高风险发布必须经过审批；预览 hash、账号、内容版本和审批编号必须绑定。
- 发布结果只接受平台回执或明确的待回执状态；HTTP 202、队列入列或本地点击不能判为成功。
- 成功、失败、待回执、取消和重试均显示原因、时间、平台、账号和任务 ID。
- 重试必须幂等，不能重复发布；平台未知结果时禁止自动重试。

### 10.2 评论、私信和微信

- 抖音评论/私信、视频号评论/私信、微信联系人/群/朋友圈/客服页面均验证读取、草稿、审批和执行状态。
- 草稿模式只写本地/平台草稿，不发送外部消息；页面必须明确“草稿”。
- 真实发送前必须有人工批准；发送后必须读回外部页面或回执，保存证据截图/文本/时间戳。
- 微信未运行、未登录、窗口不匹配、联系人不存在、平台验证码等情况必须阻止发送并说明原因。
- 账号切换、窗口切换、任务取消和断线重连不得把消息发到错误账号或错误联系人。

### 10.3 互动规则和客服

- 规则新增、优先级、启停、命中条件、回复模板和人工接管边界可验证。
- 自动回复命中后必须有规则 ID、输入、输出、审批/发送状态和审计记录。
- 规则异常或模型不可用时进入人工处理，不得静默丢失会话。

## 11. Agent-S、本地引擎和证据链

### 11.1 Agent 会话和工具

- 创建真实 session，返回可回查的 session ID；状态包含创建、就绪、运行、等待审批、成功、失败、取消、过期。
- 工具目录展示真实能力；调用前进行权限和风险检查，工具参数经过 schema 校验。
- `tool_started`、`tool_progress`、`approval_required`、`artifact_created`、`task_done` 等事件按顺序显示。
- WebSocket/SSE 断线后按 lastEventId 重放，事件去重，不重复执行和重复计费。
- Agent-S 不可用时显示 degraded/blocked 原因，不能把未执行任务显示为已完成。

### 11.2 审批和风险

- 审批内容包含动作、目标、账号、内容预览、风险等级、过期时间和预览 hash。
- 审批被拒绝、过期、目标变化、预览变化、重复消费时均阻止执行。
- 审批一次性消费；同一 confirmation ID 重放必须被拒绝或返回已消费状态。
- 低风险只读任务和高风险触达任务的策略必须可区分并可审计。

### 11.3 执行和回读证据

- 每个真实外部动作必须有任务 ID、执行记录、平台结果、回读时间和证据文件。
- “点击成功”“接口返回 200”“队列入列”都不能单独作为外部成功证据。
- 外部结果无法观察时状态为 `unknown`/`待回执`，禁止自动重试。
- 证据导出后可重新读取，文件存在、哈希一致、关联任务和租户正确。
- 清理策略只删除超过保留期且不再被审计引用的证据。

### 11.4 记忆和移动执行

- 记忆新增、搜索、按 scope 删除、远程降级和权限隔离可验证。
- Android/移动执行只接受真实设备结果；无法读回时标记 unknown，不得凭点击结果判成功。
- 设备 lease、任务 owner、审批绑定和执行证据必须一致；设备断开后任务进入可恢复失败态。

## 12. 数据一致性、并发和恢复

必须分别验证单请求、并发请求、进程重启和数据库异常：

- 两路并行加载中一路失败、一路成功时，错误状态不能被成功路径清掉。
- 连续点击创建、执行、发布、保存按钮，最多生成一个业务任务或一份审批。
- 同一任务同时取消和完成时，终态按服务端规则确定，不能出现互相矛盾的终态。
- SQLite 主库、WAL、SHM 备份/恢复按正确顺序执行；sidecar 移动失败必须阻断重建并保留原库。
- 旧库缺列/缺表时只执行明确迁移；普通数据库错误、业务错误、`P2010 no such column` 等必须分类，不能误清库。
- 解包、导入、临时目录、失败重试和未捕获异常路径都要清理临时文件。
- 跳过更新时取消正在进行的下载；下载完成与跳过竞态下不得安装已跳过版本。
- 网络断开、3011 重启、Agent-S 重启后，任务状态可恢复或明确失败，不能卡在无解释 loading。

## 13. 前端 UI、响应式和可访问性

### 13.1 路由和状态

至少覆盖以下路由组：工作台、Agent、任务、审批、证据、内容、素材、选题、模板、策略、定时任务、获客、CRM、互动、发布、本地引擎、平台账号、模型、设置、记忆和管理员页面。

每个页面验证 Loading、Empty、Data、Error、Retry、权限拒绝和成功后的清错；失败不得只渲染空数组。

### 13.2 尺寸和交互

- 360px、640px、768px、1024px、1366px/1440px 视口均无水平溢出、遮挡和不可点击按钮。
- 表格、卡片、弹窗、审批按钮、输入框和错误条尺寸稳定，长文案换行不覆盖相邻内容。
- 键盘 Tab 顺序、焦点可见、按钮/输入框有可读名称，颜色对比符合项目门禁。
- 错误条提供重试；重试按钮有 loading/禁用态，不因重复点击产生并发请求。
- 浏览器 console 不得出现未处理异常、持续 5xx 或无解释的资源失败。

### 13.3 自动化路由扫描

使用登录态运行 `frontend/scripts/console-quality-browser-scan.mjs`：

- 目标：当前路由清单全部访问成功，页面标题/核心内容存在。
- 通过条件：失败路由为 0，console error 为 0，request failure 为 0，系统 footer 全部存在。
- 报告必须保存 JSON 和 Markdown，并绑定执行时间、commit 和会话来源。

## 14. 桌面安装包和更新功能

### 14.1 安装和启动

- Windows x64 与 macOS arm64 分别安装，普通用户无需安装 Node、Python、Docker、Postgres、Redis、Chrome 或 sqlite3。
- 首次启动自动准备数据目录、启动 3011、本地引擎和浏览器；健康检查通过后才进入工作台。
- 卸载不误删用户明确保留的数据；升级不丢账号、租户、任务和证据。
- 安装路径含空格、非管理员目录和已有旧版本时仍能启动。

### 14.2 包内资源

逐包解包检查：

- `backend/index.js`、`backend/package.json`、schema、合规 `seed.db`、Node runtime、Playwright MCP、Chromium、sharp 和目标平台 Prisma engine 存在。
- Windows 包必须含 `chrome-win64`、`node.exe`、`query_engine-windows.dll.node`，不得含 Darwin engine。
- Mac 包必须含 `chrome-mac-arm64`、Mac Node、`libquery_engine-darwin-arm64.dylib.node`，不得含 Windows engine。
- 禁止普通 `.db`、`dev.db`、用户数据、账号、session、默认凭据、缓存、开发目录和绝对 symlink 进入发布物；仅允许明确的 `seed.db` 模板。
- `main.js` require 的依赖和实际包内容必须一一对应。

### 14.3 自动更新

- 检查更新、下载、跳过、下载完成、退出安装、重启和回滚均有可见状态。
- 跳过版本立即取消进行中的下载，并禁止随后安装被跳过版本。
- feed 的版本、文件名、大小、blockmap、SHA-512 与远端实际文件一致。
- 更新失败保留当前可运行版本，并显示可操作的恢复建议。

## 15. 安全、隐私和错误处理

- 日志、前端错误条和 API 响应不得泄露密码、token、Cookie、密钥、数据库连接串或完整个人信息。
- 所有写操作校验用户、租户、角色、资源 owner 和风险审批；默认 fail-closed。
- 未认证请求受保护接口返回 401；已认证但无权请求返回 403；资源不存在不泄露跨租户信息。
- 外部供应商 4xx 业务拒绝、5xx 引擎错误、网络错误、超时和额度冻结必须分类处理。
- 错误上报只记录脱敏信息；不能把 204 当作 OSS 已落库证据，需有 readback 或服务端确认。
- 防止 XSS、HTML 注入、路径穿越、任意文件读取、任意命令执行和危险 URL 跳转。

## 16. 自动化门禁要求

每次发版至少执行以下命令，完整输出写入证据目录，不使用 `tail` 截断上游失败：

```bash
# 3010/3011 已启动，且存在有效登录 token
node scripts/pre-release-full.mjs

# 包内容精确绑定到当前版本
cd desktop
node scripts/check-full-installer-assets.js --installer="dist/<mac-installer>" --platform=mac-arm64
BUILD_PLATFORM=win-x64 node scripts/check-full-installer-assets.js --installer="dist/<win-installer>" --win-only
node scripts/check-version-sync.js
node --test scripts/release-guards.test.js

# 远端发布校验
npm run release:verify:remote
node scripts/verify-mac-release.js --remote
```

当前门禁必须包括：后端/前端 tsc、后端 Jest、前端 Vitest、循环依赖、前端生产构建、SQLite bundle、商业资产、R1-R4、Mac 18 项、核心 9 项、登录态全路由扫描、L4 asar 解包和 Windows 平台资产检查。

## 17. 商业真实验收要求

使用 `scripts/commercial-acceptance-gate.mjs`，先完成只读和草稿验收，再单独申请真实外部动作。报告必须区分 `PASS`、`FAILED`、`BLOCKED` 和 `WARN`。

### 17.1 必过项目

- authentication、readiness、batch-tasks、publishing-center、permission-escape、failure-recovery、evidence-export。
- Agent-S 真实 session、浏览器控制、账号同步、任务创建、读操作和草稿任务。
- 每个真实任务都有任务 ID、执行记录、审批（如适用）和证据回读。
- 数据库计数和 API 返回必须指向同一个明确数据库模式；SQLite/PG 不得错位比较。

### 17.2 明确阻塞项目

以下项目没有用户明确批准不得自动执行，必须报告为 BLOCKED 而不是 PASS：

- 真实评论/私信/发布/群发/朋友圈发送。
- 连续内容 pipeline 循环生成。
- 真实草稿填入第三方浏览器。
- 本机微信未运行或未登录。
- 缺少测试平台账号、测试联系人、topics 或供应商凭据。

### 17.3 真实动作批准门

真实动作仅在测试账号、目标、内容、风险、审批人、时间窗口和回读方式全部记录后执行。执行前设置对应的 `COMMERCIAL_APPROVE_*` 和 `COMMERCIAL_REAL_*` 开关；执行后立即关闭，并保存完整报告。

## 18. 失败分级和放行标准

| 等级 | 定义 | 处理 |
|---|---|---|
| P0 | 数据泄露、越权、误发布、假成功、无法启动、包缺关键运行时 | 立即阻断，不得发版 |
| P1 | 核心业务闭环失败、审批可绕过、错误被静默、真实执行无证据、跨平台资源串包 | 修复并重新跑相关全量门禁 |
| P2 | 非核心体验、文案、布局、低风险边界或测试工具缺陷 | 记录负责人和期限；不得掩盖 P0/P1 |
| BLOCKED | 环境/人工确认/第三方条件缺失，尚未证明 | 保留阻塞原因，不得计入通过率 |
| WARN | 非阻断提示，已知且不影响当前范围 | 必须写明影响和后续处理 |

发版放行必须同时满足：

1. P0/P1 缺陷为 0，所有 BLOCKED 已明确列出且不被宣称为通过。
2. 完整自动门禁 17/17 通过，release guards 全部通过。
3. 登录态路由扫描失败为 0，控制台错误和请求失败为 0。
4. 真实 Agent-S 读/草稿闭环通过，真实外部发布若未批准则明确阻塞。
5. 双平台包精确绑定当前版本，包内资源检查通过，远端 feed、安装包、blockmap 和哈希一致。
6. 证据可从仓库/证据目录和任务系统复查，且不含秘密。
