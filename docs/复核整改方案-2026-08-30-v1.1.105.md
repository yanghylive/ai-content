## 2. P1 整改项

### P1-1：L4 必须绑定精确发布包

**现状**

- `check-package-contents.js` 已按版本号选最新 exe，但 `pre-release-full.mjs` 调用时没有传 `--win-only`，平台互斥分支不会执行。
- `check-full-installer-assets.js` 仍固定读取 `dist/win-unpacked`；`pre-release-full.mjs` 只判断目录中是否存在任意 Setup exe。
- 中间目录与最终 exe 不一致时，未来仍可能出现假绿。

**修改方案**

1. `pre-release-full.mjs` 显式传 `--win-only`。
2. 给 `check-full-installer-assets.js` 增加 `--installer=<path>`，直接解包并检查指定 exe，禁止回退到中间目录。
3. 在 `pre-release-full.mjs` 按语义版本选出唯一最新 Windows exe，并把路径传入严格门禁。
4. 仅在显式 `--dir=dist/win-unpacked` 时允许检查中间目录。
5. 增加 `mac-arm64` 的 Node、Chromium、Prisma engine 平台互斥检查。

**验收命令**

```bash
cd "/Users/yanghy/Documents/New project/ai-content"
node desktop/scripts/check-package-contents.js --dir dist --win-only
BUILD_PLATFORM=win-x64 node desktop/scripts/check-full-installer-assets.js --phase=post --installer="desktop/dist/JIUZHANG AI 内容创作平台 Setup 1.1.105.exe"
node scripts/pre-release-full.mjs --only=L4
```

验收日志必须明确显示读取的是 `1.1.105.exe`，不能只显示 `win-unpacked`。

涉及文件：[pre-release-full.mjs](/Users/yanghy/Documents/New%20project/ai-content/scripts/pre-release-full.mjs:120)、[check-package-contents.js](/Users/yanghy/Documents/New%20project/ai-content/desktop/scripts/check-package-contents.js:163)、[check-full-installer-assets.js](/Users/yanghy/Documents/New%20project/ai-content/desktop/scripts/check-full-installer-assets.js:30)。

### P1-4：修正登录态路由扫描证据

最新扫描虽显示 149 路由无控制台错误，但 `localAcceptanceSession=false`、`systemFooterPassCount=0`，不能作为登录态商业验收。

**修改方案**

1. 扫描前用测试账号创建一次性 session/token。
2. 设置 `CONSOLE_SCAN_LOCAL_ACCEPTANCE_LOGIN=1` 并传入有效 token。
3. 把 `localAcceptanceSession=true`、关键 footer 状态、无认证重定向设为硬断言。
4. 空 token、过期 token 或 `/login` 重定向直接失败。

通过标准：`routeCount=149`、`localAcceptanceSession=true`、`systemFooterPassCount>0`、`consoleErrors=[]`、`requestFailures=[]`、`authRedirects=[]`。涉及脚本：`frontend/scripts/console-quality-browser-scan.mjs`。

## 3. P2 整改项

### P2-1：明确遗留 Cloud API 的产品边界

桌面端仍有 `/auth/login`、`/usage/stats`、`/subscription` 等调用；云端服务要求 `x-api-key`，桌面端通用请求发送 `Authorization: Bearer`，且服务端未实现这些认证/订阅路由。

二选一：

- 若已移出产品范围：移除/隐藏桌面 IPC 和适配器调用，补测试，并在验收清单标为遗留禁用；
- 若仍属于产品范围：实现完整接口并统一鉴权协议，绝不能把共享 `API_KEY` 下发到安装包。

涉及文件：`desktop/cloud-api.js`、`frontend/src/lib/cloud-api-adapter.ts`、`cloud-api-server/server.js`、`backend/src/modules/cloud-api/`。

### P2-2：补齐数据库自愈时序测试

对 [main.js](/Users/yanghy/Documents/New%20project/ai-content/desktop/main.js:1606) 增加测试覆盖：stderr 写流 flush 后再读取、日志轮转/截断、WAL/SHM rename 失败、自愈失败后的重试上限、`.corrupt-*` 备份可恢复。WAL rename 失败时不能继续对外宣称“自愈完整”。
