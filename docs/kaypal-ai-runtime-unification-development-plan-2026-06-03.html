3010 / 3011 / 5409 终极代码合并开发方案

本方案目标只有一个：完成终极代码合并。3010 保留为唯一用户界面，3011 保留为 Core API， 5409 不再作为独立项目和独立前端存在，其浏览器 CDP 能力迁入 Kaypal Local Runtime。 微信/桌面应用执行（与 5409 无关）仍由 Agent-S 承担，不进入 Runtime。

前置声明（不可变）：本次合并不改变 Agent-S 在微信和桌面应用互动中的主执行器地位； 不改变默认 auto-send 行为；local-engine 仅做权限、策略、状态、证据、审计，不替代 Agent-S。 桌面互动路径与浏览器 CDP 路径并行，由 3011 ExecutorRouter 路由，不合并成同一个执行器。

一、6 个专家会议结论

产品负责人

用户入口

用户不应该知道 3011 和 5409。所有功能、状态、失败原因、账号配置、证据记录都必须回到 3010。

结论：3010 是唯一用户入口，不再暴露 5409 页面。

后端架构专家

业务中枢

3011 必须成为唯一业务调度层。前端不能绕过 3011 直发 worker 或 Agent-S RPC；Agent-S Hook 只做 UI 状态编排，真实执行仍走 3011 ExecutorRouter，分发到 LocalRuntimeClient 或 AgentSClient。

结论：先建 ExecutorRouter（含 LocalRuntimeClient + AgentSClient），再逐步迁移 5409 浏览器能力。

桌面端专家

一键启动

商用用户不应该手动管理多个进程。桌面 App 要负责拉起 3010/3011/Local Runtime/Agent-S、健康检查、权限提醒、端口冲突处理。

结论：桌面端是进程管理器和权限向导，不是另一个业务入口。

自动化执行专家

真实执行

5409 里有浏览器 CDP 执行经验，迁入 Local Runtime；微信和桌面应用互动仍由 Agent-S 执行，Runtime 不接管。两条路径并存，由 3011 路由。

结论：5409 作为独立项目消失；浏览器路径 → Local Runtime，桌面路径 → Agent-S。

安全与审计专家

不能假成功

发布、评论、私信不能只看 task completed。必须有发送动作、页面回读、截图/文本证据和失败原因；Agent-S 路径需附 trajectory 或 action log 之一。

结论：统一 Evidence 同时支持 Local Runtime 和 Agent-S，不认裸 sent=true。

QA / 交付专家

验收

验收必须按业务链路，不按按钮可点击。重点是抖音/视频号 4 条互动闭环、微信会话/群发/朋友圈 Agent-S 闭环、发布闭环、账号过期、Local Runtime / Agent-S 断开、权限缺失。

结论：每条链路必须有可复跑脚本和页面证据，微信路径必须命中 Agent-S。

→

Python 执行引擎（浏览器 CDP）。负责打开抖音/视频号、控制浏览器、发送、发布、截图回读。

http://127.0.0.1:5409
＋

Agent-S

桌面应用执行器。负责微信会话/群发/朋友圈等桌面客户端互动；当前由前端 Hook 直拉，3011 侧未完全收口。

local-controller (IPC)
组件 当前职责 当前问题 终局归属
3010 页面和用户操作入口 部分入口会让用户意识到 5409 的存在；运行检查和执行状态还没有完全产品化 唯一用户入口
3011 业务 API 和调度层 调用 5409 的路径分散；Agent-S 调用层未在 3011 收口，证据流向不统一；Runtime 能力还没有完全抽象 唯一业务中枢（含 ExecutorRouter）
5409 Python 本地执行引擎，有独立前端和 API 用户能打开独立页面；账号/任务/日志会形成第二套认知 拆成 Kaypal Local Runtime（仅浏览器 CDP 路径）
Agent-S 桌面应用自动化执行（微信、桌面互动） 启动依赖手工，权限引导和进程守护未收口；证据未统一入 EvidenceService 执行器不变，启动和证据上报统一收口
local-engine 权限/策略/状态/证据/审计支持 边界容易被误解为执行器 仅做协调，明确不承接桌面执行
Desktop Electron 打包和启动 需要进一步收口为一键启动、健康检查、权限引导、更新管理 本地进程管理器 + 权限向导（含 Agent-S 守护）

三、终极架构

KaypalAI 内容创作平台.app
  ├─ 打开唯一入口: http://127.0.0.1:3010
  ├─ 启动 Core API: 3011
  ├─ 启动 Local Runtime: 内部端口或进程 IPC
  ├─ 守护 Agent-S / local-controller (桌面互动主执行器)
  └─ 负责健康检查、权限提醒、端口冲突、更新

3010 Web UI
  ├─ 只调用 3011 /api
  └─ use-agent-s-state Hook 仅做 UI 状态编排，不直发 Agent-S RPC

3011 Core API
  ├─ Auth / Kaypal 授权
  ├─ AccountProfileService
  ├─ Material / Topic / Article / Publishing
  ├─ Interaction Orchestrator
  ├─ ExecutorRouter            ← 按任务类型分发
  │    ├─ 浏览器 CDP 任务  → LocalRuntimeClient
  │    └─ 桌面应用任务     → AgentSClient (微信/桌面互动)
  ├─ EvidenceService           ← 同时收 Runtime + Agent-S 证据
  └─ AuditLogService

Kaypal Local Runtime (浏览器 CDP 路径)
  ├─ BrowserControl
  ├─ AccountProfile
  ├─ PlatformPublisher         (抖音 / 视频号 / 图文视频发布)
  ├─ InteractionExecutor       (抖音/视频号 评论/私信)
  ├─ ReadbackVerifier
  └─ EvidenceCapture

Agent-S / local-controller (桌面应用路径，执行器不变)
  ├─ 微信会话 / 群发 / 朋友圈
  ├─ 其它桌面客户端互动
  ├─ trajectory / action log → EvidenceService (本期新接，任一即可)
  └─ local-engine 仅做权限/策略/状态协调，不替代执行
最终判断标准：用户只启动 KaypalAI 内容创作平台，只访问 3010；任何真实平台动作由 3011 创建任务、 ExecutorRouter 决定走 Local Runtime 还是 Agent-S、3011 保存证据、3010 展示结果。 微信和桌面互动路径必须命中 Agent-S，否则视为护栏违规。

天级任务拆分

下面以"工作日"为粒度展开每阶段。所有阶段进入前必须满足"入口"，完成后必须达到"出口"。同名验收口径与 P5 八节验收一致，不重复列。

P1 · 边界 + 路由 (2-3 天)

基础设施

入口：当前代码可正常启动；3010 + 3011 + 5409 链路 e2e 通过。

  • D1：仓库根写 P1 声明文件；全仓扫描 5409 / auto-upload / Agent-S / local-engine / 127.0.0.1:，补全十节文件清单。
  • D2：建 backend/src/modules/runtime/ 骨架；定义 RuntimeExecutionResult、reasonCode、evidence 类型；ExecutorRouter 空骨架（未注册任务默认 reject）。
  • D3：实现 LocalRuntimeClient（透传到 AutoUploadClient，行为不变）+ AgentSClient（收口现有 Agent-S 调用，统一返回 RuntimeExecutionResult）；单元测试枚举全部任务类型。

出口：3011 编译通过；所有现网 e2e 用例改走 ExecutorRouter 后仍通过；微信/桌面任务无 Runtime 误派。

产出：runtime 模块骨架、ExecutorRouter 单测、十节文件清单 v1。

P2 · 浏览器能力 Copy-first (5-8 天)

  • D4：新建 runtime/agent-s-adapter.ts（薄壳包装 AgentSService）；加入 ExecutorRouter.executors；单测 3 个 case；可选起 desktop/runtime-launcher.js 草案。

P3 · 切上层 + 双跑 + 删存量 + 5409 下线 (3-5 天)

高风险

入口：P2 出口达成；两套代码都跑得通。

  • D2-D3：双跑灰度 ≥ 3 天，抖音/视频号 4 条互动各 5 轮，新旧路径结果比对，差异为零（或全部解释清楚）。

产出：切换 PR、双跑差异报告、存量删除 PR、legacy tag。

P4 · 桌面端集成 + Agent-S 守护 (3-4 天)

桌面

入口：P2 完成（不依赖 P3 是否下线 5409，可与 P3 并行）。

  • D1：Electron 主进程改造为多进程编排（3010/3011/Runtime/Agent-S）；端口冲突自动 fallback；启动顺序与超时设计。
  • D2：写 runtime-manifest.json；3010/3011 读 manifest 获取 Agent-S endpoint；进程 PID 文件 + 启动前清理同名进程。
  • D3：首次启动引导页——四项 macOS 权限（辅助功能、自动化、文件访问、屏幕录制）逐项检查与跳转；未授权阻塞执行。
  • D4（缓冲）：心跳 + 5s 强杀僵尸；退出钩子统一信号；崩溃日志收集到 3010 设置页。

出口：双击 App 后无需终端；四件套全部起来；任一进程挂掉 3010 能在 5s 内反映状态并自恢复或明示阻塞。

产出：Electron 编排代码、runtime-manifest.json、权限引导页、打包后的 .app。

P5 · 终极回归验收 (3-5 天)

验收

入口：P3 + P4 均完成；八节验收 9 项口径就位；测试账号已登录、permission 已授权。

  • D1：抖音/视频号 4 条互动（评论 × 2 + 私信 × 2）各 5 轮，全部 Local Runtime 路径，3010 可查证据。
  • D2：微信会话 / 群发 / 朋友圈 各 5 轮，全部 Agent-S 路径，trajectory 或 action log 入库；混路用例必须 reject。

  • D4：失败链路覆盖——账号过期 / 验证码 / 权限缺失 / 目标为空 / 回读失败 / Local Runtime 断开 / Agent-S 断开 / 证据写入失败；全部不能显示 success。
  • D5（缓冲）：整理证据；产出验收报告；交接 docs/handover-2026-06-03.md 更新。

五、第一轮具体改造清单

3010 前端

  • 删除或隐藏所有直接打开 http://127.0.0.1:5409 的入口。
  • 运行检查页改成"本地执行引擎状态"，并行展示 Local Runtime 与 Agent-S 两路状态，不显示技术端口为主信息。
  • 发布中心、客户互动、账号设备全部只走 3011 API。
  • 保留 use-agent-s-state.ts Hook 做 UI 状态编排（启动/轮询/取消），Hook 内部只调 3011 API，由 ExecutorRouter 路由到 AgentSClient，不直连 Agent-S RPC，也不切到 Local Runtime。
  • 默认 auto-send，不增加额外审批入口；仅在不确定目标/风险内容/权限缺失时弹审批。
  • 失败状态统一展示：未启动、未登录、验证码、权限缺失、平台页面变化、回读失败、Local Runtime 不可用、Agent-S 不可用。

3011 后端

  • 新增 backend/src/modules/runtime/。
  • 把 AutoUploadClient 包进 LocalRuntimeClient。
  • 新增 ExecutorRouter：浏览器任务 → LocalRuntimeClient，桌面任务 → AgentSClient。
  • backend/src/modules/local-engine 保持支持角色，不承接执行；不引入微信执行能力。
  • 所有执行返回统一 RuntimeExecutionResult。
  • 所有证据保存到统一 EvidenceService，不让前端猜成功；Agent-S 的 trajectory 或 action log 一并入库。

5409 / auto-upload

  • 按模块迁移，不保留独立产品形态；仅迁浏览器 CDP 侧能力。
  • 把 main.py 中的平台 API 拆成 Runtime handlers。
  • 把 cdp_runtime.py、platform_douyin_cdp.py、platform_channel_cdp.py 迁入 Runtime。
  • 微信/桌面相关脚本（若有）不迁入 Runtime，统一由 Agent-S 接管，必要时只做废弃。
  • 迁移完成后移除 5409 固定端口和自带前端。

Desktop

  • 启动时检查 3010/3011/Runtime/Agent-S 是否占用，冲突则自动换端口或提示。
  • 写 runtime-manifest.json 给 3010/3011 读取，含 Agent-S endpoint。
  • 首次启动引导四项 macOS 权限：辅助功能、自动化、文件访问、屏幕录制（最后一项为 Agent-S 必需）。
  • 打包时把 Runtime 和 Agent-S 启动器作为内部资源，不依赖用户本机路径。

六、统一数据契约

type RuntimeExecutionResult = {
  ok: boolean;
  status: 'success' | 'failed' | 'blocked' | 'skipped';
  reasonCode:
    | 'runtime_unavailable'
    | 'agent_s_unavailable'
    | 'account_not_logged_in'
    | 'captcha_required'
    | 'permission_missing'
    | 'review_required'
    | 'target_not_found'
    | 'send_failed'
    | 'readback_failed'
    | 'platform_changed'
    | 'success';
  userMessage: string;
  technicalMessage?: string;
  runtime: {
    mode: 'local-runtime' | 'agent-s' | 'auto-upload-worker';
    executor: 'browser-cdp' | 'desktop-agent-s';
    version?: string;
    engineUrl?: string;
    profileDir?: string;
    cdpPort?: number;
    agentSSessionId?: string;
  };
  evidence: Array<{
    type:
      | 'screenshot'
      | 'text'
      | 'page-url'
      | 'network'
      | 'readback'
      | 'agent-s-trajectory'
      | 'agent-s-action-log';
    label: string;
    value?: string;
    path?: string;
    createdAt: string;
  }>;
  readback?: {
    expectedText?: string;
    actualText?: string;
    matched: boolean;
  };
};
关键规则：前端不能因为 completed 显示回读成功；后端不能因为 sent=true 判定真实成功； 微信/桌面任务必须含 agent-s-trajectory 或 agent-s-action-log 证据，否则视为未真实执行。

七、不能做的事

  • 不能在 P2 完成迁移、P3 双跑无差异之前删除 5409。它里面有已经跑通过的浏览器执行经验，提前删会倒退。
  • 不能让 3010 前端直接调 5409。这样会形成第二套入口和第二套状态。
  • 不能让 3010 前端绕过 3011 直发 Agent-S RPC。Hook 只做 UI 状态编排，业务调用仍走 3011 ExecutorRouter。
  • 不能把 5409 整个 Python 项目原封不动塞进 3011。3011 会变成不可维护的混合执行层。
  • 不能只做 UI 隐藏，不做错误码和证据统一。否则商用时还是会假成功。
  • 不能把微信会话、群发、朋友圈或任意桌面应用互动从 Agent-S 切到 Local Runtime / local-engine。
  • 不能让 local-engine 模块承担桌面客户互动的主执行；它只做权限、策略、状态、证据、审计协调。
  • 不能改变默认 auto-send 行为；不能把客户互动改成"任务创建即算完成"。
  • 不能用任务生命周期或执行记录代替真实客户回复/发送的证据。

八、验收标准

验收项 通过标准
单入口 用户只打开 3010；页面上没有 5409 作为独立产品入口。
启动 桌面 App 一键启动 3010、3011、Local Runtime、Agent-S；失败能显示具体原因。
执行路径分离 抖音/视频号任务命中 Local Runtime；微信会话/群发/朋友圈任务命中 Agent-S；混用即不通过。
客户互动 - 浏览器 抖音评论、抖音私信、视频号评论、视频号私信各连续 5 轮真实读、生成、发送、回读。
客户互动 - 桌面 微信会话、微信群发、朋友圈各连续 5 轮真实读、生成、发送，全部经 Agent-S，附 trajectory 或 action log 证据。
默认发送模式 默认 auto-send 生效；审批仅在不确定目标、风险内容、权限缺失或用户显式选择时出现。
发布中心 图文和视频发布有真实上传、发布、平台结果或页面回读。
失败处理 Local Runtime 断开、Agent-S 断开、账号过期、验证码、权限缺失、目标为空、回读失败都不能显示成功。
证据 每个真实执行任务都有日志、截图或文本证据；微信路径必须含 Agent-S trajectory 或 action log，可在 3010 查看。
