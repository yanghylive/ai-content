# 增长获客商用级 UX 优化开发文档

Hallmark · pre-emit critique: P5 H5 E4 S5 R4 V4

## 目标

把增长获客板块从“功能可用”升级到“商业运营人员可以长期使用”的工作台。范围覆盖：

- 获客总览：`/growth`
- 自动获客矩阵：`/growth/acquisition`
- 获客策略：`/growth/strategies`
- 线索池：`/growth/leads`
- 账号健康：`/growth/account-health`
- 增长复盘：`/growth/reports`
- 增长工作流：`/growth/workflows`

本轮不做 CRM 系统重复建设，不接 CRM 外部系统；只做增长获客内部的线索、任务、策略、账号、复盘和 SOP 体验闭环，并为后续 CRM 接入保留清晰入口。

## 不可妥协标准

1. 表单必须一眼看出可输入、可选择、禁用和只读状态。
2. 所有输入框、下拉框、日期框、搜索框必须同一高度、同一边框语义、文字垂直居中。
3. 页面主操作必须跟当前页面相关，不能所有页面都用同一套顶部按钮。
4. 真实执行、演练模式、平台能力、后台调度、账号可用性必须明确展示。
5. 空状态必须给下一步动作，不允许只显示“暂无数据”。
6. 表格必须支持真实数据规模：搜索、筛选、排序语义、批量操作、横向溢出处理。
7. 危险操作必须确认；批量操作必须说明影响范围。
8. 执行失败、风控阻断、账号不可用必须有原因、证据和下一步。
9. 工作流步骤不能因为没保存备注而丢失用户输入。
10. 移动端和窄屏不能横向炸版，按钮文字不能换成两行。

## 商用品质验收

- 视觉：所有增长页表单控件、筛选区、操作按钮、表格密度一致。
- 可理解：每页顶部能说明“现在能不能真实执行、为什么不能、下一步做什么”。
- 可操作：每个空状态至少有一个可执行 CTA。
- 可追责：执行记录、线索、账号、策略、工作流之间能互相定位。
- 可扩展：新增平台或新增执行器时，不需要重新解释整个 UI。
- 可验证：`tsc` 通过，核心页面浏览器截图无错位，关键用户流可点击。

## 6 个专家分工

### 1. UX 系统专家

职责：

- 建立增长获客统一页面壳、表单控件、筛选条、状态条、空状态、表格外壳。
- 修复输入框、下拉框、日期框、搜索框的高度、文字居中、label 位置和状态表现。
- 输出可复用组件，避免每页单独补丁。

负责文件：

- `frontend/src/app/globals.css`
- `frontend/src/components/growth/growth-console.tsx`

验收：

- 7 个增长页面所有输入类控件视觉一致。
- 下拉选项文字垂直居中，框高不夸张。
- 搜索框、日期框、select、textarea 都有清楚边界和聚焦态。

### 2. 自动获客任务专家

职责：

- 重构自动获客矩阵表单的信息结构。
- 按玩法展示不同输入提示和风险提示。
- 强化任务队列、预检、真实执行/演练状态展示。
- 任务列表增加更清晰的操作层级。

负责区域：

- `GrowthAcquisitionPage`
- acquisition task table
- preflight modal

验收：

- 用户知道创建的是哪类任务、由哪个账号执行、是否会真实触达。
- 账号不可用时能直接去账号健康或授权入口。
- 到期计划、预检、执行结果的关系清楚。

### 3. 策略与工作流专家

职责：

- 策略生成从“行业/场景”升级为可运营的策略资产。
- 增加策略搜索、版本/复核感、套用说明、删除确认。
- 工作流模板选中态、步骤状态、备注保存和完成动作闭环。

负责区域：

- `GrowthStrategiesPage`
- `StrategyCard`
- strategy modals
- `GrowthWorkflowsPage`
- `WorkflowCard`

验收：

- 策略可查看、编辑、复制、删除、套用，且动作风险清晰。
- 工作流像 SOP 管理，不像静态模板列表。
- 完成步骤前不会丢备注。

### 4. 线索运营专家

职责：

- 优化线索池管理体验。
- 手动补充线索区域可折叠或不干扰表格管理。
- 批量操作有确认、影响范围、撤销/备注语义。
- 线索详情按基本信息、跟进、去重、证据分区。

负责区域：

- `GrowthLeadsPage`
- lead table
- `LeadDetailModal`
- `BulkLeadActions`

验收：

- 线索表能处理真实数据，不被左侧表单压缩。
- 用户能快速跟进、改状态、看证据。
- 批量操作不误伤。

### 5. 账号健康与复盘专家

职责：

- 把账号健康从普通表格升级为风控指挥面板。
- 增长复盘增加真实分析感：漏斗、趋势、瓶颈、导出说明。
- 报表和账号页提供修复动作入口。

负责区域：

- `GrowthAccountHealthPage`
- `GrowthReportsPage`
- report tables

验收：

- 可用账号、风险账号、需验证账号一眼可见。
- 复盘不只是 0 数据列表，而能解释原因和下一步。
- 导出行为和导出内容明确。

### 6. 商用验证专家

职责：

- 建立验收脚本和手工测试清单。
- 覆盖 7 个页面的桌面、窄屏、空数据、有数据、失败状态。
- 检查控制台错误、布局错位、按钮换行、表格溢出。

负责文件：

- `scripts/`
- `docs/acceptance-evidence-*`

验收：

- `npm run typecheck` 或等价 `tsc --noEmit` 通过。
- 浏览器验收覆盖所有增长页。
- 输出截图和结果记录。

## 工期

6 人并行，按商用级一次做完，不做 MVP。

### 第 0.5 天：系统基线

- UX 系统专家完成统一控件和页面壳。
- 其余专家阅读文档、锁定各自页面问题和代码范围。

### 第 1 天：核心体验重构

- 自动获客、策略、线索池、账号健康、复盘、工作流并行重构。
- 主线程负责公共组件抽取和冲突收敛。

### 第 1.5 天：闭环与异常态

- 补齐空状态、失败态、确认弹窗、状态说明、跨页跳转。
- 修复表格、批量操作、导出、备注保存风险。

### 第 2 天：商用验收

- 类型检查、构建检查、浏览器截图。
- 7 个页面逐页验收。
- 修复剩余错位、换行、不可点击、异常提示问题。

如果只在当前连续开发会话里推进，执行顺序压缩为：

1. 文档落地。
2. 6 个专家并行拆页修改。
3. 主线程抽公共组件。
4. 主线程整合并跑测试。
5. 浏览器逐页验收。

## 页面级改造清单

### 获客总览

- KPI 卡片改为真实业务语义：新增、触达、高意向、风险。
- 增加就绪状态条：执行模式、调度状态、平台支持、账号健康。
- 最新线索增加打开来源、查看详情、快速跟进。
- 空状态增加创建获客任务和导入线索入口。

### 自动获客矩阵

- 表单按“目标 / 平台账号 / 来源 / 话术 / 风控 / 计划”分组。
- 根据获客玩法切换输入说明。
- 明确“真实执行 / 安全演练 / 仅草稿”。
- 到期任务队列提供预检原因和可执行动作。
- 配置表增加搜索、状态筛选、批量启停语义。

### 获客策略

- 策略生成增加目标客户、地区、客单价、禁用词、平台偏好。
- 策略卡展示评分原因、覆盖度、风险项。
- 删除、套用、覆盖任务必须确认。
- 再生成策略提供“新版本/替换/复制”语义。

### 线索池

- 手动补充线索改为可折叠面板。
- 表格增加密度、横向滚动、批量操作确认。
- 状态流转完整展示。
- 详情弹窗分区并补充证据、跟进、去重入口。

### 账号健康

- 顶部增加账号状态汇总。
- 风险表按严重度排序。
- 冷却、恢复、重检进入明确操作流。
- 每个风险项提供修复动作。

### 增长复盘

- 增加漏斗视图、趋势解释、瓶颈处理动作。
- 导出 CSV/快照说明内容范围。
- 表格支持点击跳到任务、账号或线索。
- 空数据说明原因。

### 增长工作流

- 模板选中态明确。
- 工作流步骤有状态、备注、保存、完成、回退。
- 完成步骤前自动保存备注。
- 空状态直接给模板 CTA。

## 技术实现原则

- 不删除现有路由。
- 不重写 CRM 系统。
- 不把页面做成营销落地页；增长获客是运营工作台，必须信息密度高、动作清晰。
- 优先抽公共组件，不在 7 个页面重复写样式。
- 所有危险动作统一确认弹窗。
- 所有表格容器统一支持横向滚动和数字等宽。
- 所有按钮一行显示，不允许窄屏换两行。

## 验证清单

- 类型检查：前端 TypeScript。
- 视觉检查：7 个页面桌面宽屏、1365px、768px。
- 控件检查：输入、select、textarea、date、search。
- 操作检查：创建任务、生成策略、套用策略、添加线索、批量改状态、账号冷却、导出报表、创建工作流。
- 异常检查：无账号、无策略、无线索、调度关闭、平台不支持、执行失败。
- 可访问性检查：按钮 aria-label、表单 label、焦点态。

## 本轮完成定义

本轮完成后，增长获客板块必须满足：

- 用户看得出哪里能输入。
- 用户知道当前系统能不能真实执行。
- 用户知道为什么不能执行。
- 用户能从任一空状态进入下一步。
- 用户能管理策略、任务、线索、账号、复盘和 SOP。
- 用户不会因为 UI 错位、控件不齐、按钮挤压而觉得系统是半成品。
