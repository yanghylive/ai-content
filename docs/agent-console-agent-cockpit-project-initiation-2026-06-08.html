KaypalAI Agent 操作驾驶台升级项目

将 http://localhost:3010/agent-console 从“本机 Agent 指令表单”升级为多用途 Agent 操作驾驶台： 既能像 ChatGPT 桌面版一样完成聊天、写作、文件分析，也能控制本地电脑、浏览器、文件和业务后台，并把执行过程纳入确认、证据和交付闭环。

主 UI 决策：主骨架采用 AI Dashboard Canvas Agent 的“Chat + Persistent Canvas”模式； 局部交互吸收 MCP Apps Generative UI Showcase 的内嵌操作面板、 Generative UI Starter Project 的共享任务状态、 AI Shadcn Component Generator 的组件白名单思想。 右侧 Canvas 的定位是 Codex 式当前任务工作区：展示当前任务生成的草稿、浏览器/文件/发布预览、确认卡、证据和交付物； 不做全局状态看板，不重复展示系统其他页面已有的任务数量、确认数量和证据总数。
PRD 产品需求用户流程、功能范围、角色和场景。 UI 信息架构ChatGPT 桌面版 + 当前任务工作区。 技术设计组件、状态、接口和兼容策略。 API Contract任务草稿、Surface、阻断和证据合同。 Surface CatalogAgent 可生成 UI 面板白名单。 安全权限规则确认、风控、权限和禁止动作。 验收测试清单聊天、本机、浏览器、文件、确认和证据。 开发任务拆解Sprint、任务包、依赖和交付顺序。

1. 项目背景

当前页面现状

已具备基础能力

/agent-console 当前可以创建本机 Agent 会话，支持执行范围、目标平台、预检阻断、本机引擎状态、确认队列和证据入口。

  • 主页面仍以“输入指令 + 选择范围 + 填目标应用”的表单为中心。
  • 用户需要自己理解执行条件、平台账号、确认边界和下一步入口。
  • 运行状态、待确认、证据、任务记录已有独立页面；新入口缺的是把“当前这件事”组织成可操作工作区。

升级机会

产品定位升级

用户真正需要的是一个桌面 Agent 驾驶台，而不是一个命令提交表单，也不是另一个后台监控面板。Chat 是入口，右侧 Canvas 是当前任务工作区。

  • 普通问题走 Chat 体验，像 ChatGPT 桌面版一样自然对话。
  • 真实动作自动升级为任务计划、权限预检、确认执行和证据沉淀。
  • 本地电脑、浏览器、文件、发布、互动和远程服务统一进入一个操作控制面。

2. 项目目标

统一入口

Chat first

用户用自然语言发起问答、内容生成、文件分析、本机控制和业务任务。

执行现场

Cockpit

当前任务的草稿、步骤、确认卡、证据、预览和产物持续显示，不丢在聊天记录里。

安全治理

Approval

发布、发送、删除、改文件、账号操作等高风险动作必须进入确认队列。

业务闭环

Delivery

执行结果能回到文章库、发布中心、互动中心、证据库和任务记录。

成功状态：用户可以在一个页面里完成“问一句话 -> AI 生成任务草稿 -> 补齐平台/账号 -> 确认风险 -> 本机执行 -> 查看证据 -> 交付结果”的完整链路。

4. 产品形态

左栏：会话与任务
普通聊天
本地电脑任务
浏览器任务
文件任务
等待确认
已完成 / 有证据
中区：Chat + 任务草稿
用户自然语言输入：打开抖音后台整理未回复评论。
AI 回复概要：我会先读取未回复评论，只生成建议回复，发送前等你确认。
生成任务草稿：平台、账号、执行范围、步骤、风险等级、确认点。
用户可直接修改草稿字段，而不是重写提示词。
右栏：当前任务工作区
任务草稿：我理解成什么事、要操作哪个平台、有哪些步骤。
操作画面：浏览器/文件/发布预览/评论回复草稿。
确认卡：发送、发布、删除、改文件前的明确风险和按钮。
证据卡：只展示当前任务相关截图、页面快照、日志和文件。
交付物：生成的文章、回复建议、报告、导出文件或打开结果。

5. 核心用户流程

1

自然语言输入

用户像聊天一样描述目标。

2

意图路由

系统判断是普通聊天、文件分析、本机操作还是业务任务。

3

任务草稿

生成结构化字段和步骤，展示缺失条件。

4

预检补齐

检查本机引擎、账号、平台、权限和风险。

5

确认执行

高风险动作进入待我确认，低风险动作可直接执行。

6

证据交付

沉淀截图、日志、文件和业务结果。

6. 功能范围

模块 首期能力 关键验收
多用途 Chat 入口 支持普通问答、写作、文件分析、本机任务发起；保留当前指令输入能力。 用户无需先选择复杂模式，即可从一句话进入正确流程。
任务草稿生成 把用户指令解析成任务类型、执行范围、目标平台、账号需求、步骤、风险等级和确认点。 浏览器任务缺平台/账号时，页面给出可点击补齐项，而不是只显示阻断文案。
当前任务工作区 持续展示当前任务的草稿、预览、确认卡、证据卡和交付物。 用户无需离开对话即可看到“这件事”的下一步、风险和结果；全局统计不作为主内容。
操作面板 评论处理、发布确认、文件整理、远程检查等场景提供专用 UI block。 至少完成 3 个白名单面板：任务计划、确认审批、证据列表。
确认与风控 复用现有 /confirmations、risk policy、blocker 和 commercial permission 机制。 发布、发送、删除、改文件类动作不能绕过确认。
证据与交付 复用 session events、evidence export、artifacts 页面能力，驾驶台聚合展示。 每个真实执行任务至少有时间线；有工具动作时必须产生证据摘要。

8. 数据与接口改造

接口/数据 现状 改造建议
createAgentSession 直接传 instruction、executionScope、targetApp、source。 增加可选 taskDraft、surfaceState、approvalPolicy 字段，保持旧字段兼容。
AgentSession.events 已有事件、证据、错误和状态。 增加当前任务投影模型，把事件分组为 steps、evidence、confirmations、deliverables；仅为当前任务服务。
LocalEngineActionBlocker 用于阻断提示。 扩展 resolutionActions，让阻断项可以直接提供补齐按钮。
确认队列 独立页面处理。 只在当前任务需要用户决策时渲染确认卡；全局确认列表仍留在独立确认页。
证据导出 任务记录和操作证据页可导出。 Canvas 提供当前任务证据卡和导出入口；不显示全局证据总数。

11. 验收标准

功能验收

必须通过
  • 普通聊天不创建本机任务，也不误触真实操作。
  • 浏览器任务缺平台或账号时，驾驶台展示可操作补齐项。
  • 用户确认后可创建 Agent session，并在右侧看到当前任务工作区更新。
  • 高风险动作必须进入确认队列，不能从 Chat 直接执行。
  • 任务完成后能看到当前任务证据和交付物，并可跳转任务记录或导出证据。

质量验收

工程标准
  • 不破坏现有 /agent-console、/confirmations、/execution-records、/artifacts 路由。
  • 首屏在 1280px 和 375px 宽度下无明显内容重叠。
  • 核心组件有单测或最小浏览器验收脚本。
  • 旧版创建任务流程保留兼容，不阻断商业验收脚本。

12. 风险与边界

风险 处理策略
把页面做成万能聊天框，真实任务不可控 Chat 只做入口；真实动作必须升级为任务草稿、预检、确认和证据。
模型生成任意 UI 或代码导致安全问题 只允许输出白名单 Surface JSON，由前端受控渲染。
新驾驶台绕过现有确认队列 确认逻辑仍调用原 confirmations 接口，驾驶台只做聚合入口。
把右侧做成后台监控面板，重复已有页面能力 右侧只服务当前任务和当前对话；health、sessions、confirmations、evidence 只是后台信号，不作为主 UI 数字看板。
首期范围过大 先做任务草稿、驾驶台骨架、确认/证据聚合；动态 MCP App 和任意小工具生成放到实验区。

13. 立项结论

建议正式立项。该项目不是简单 UI 美化，而是把 /agent-console 从“任务创建表单”升级为 KaypalAI 内容创作平台的多用途桌面 Agent 控制入口。

主 UI 采用 AI Dashboard Canvas Agent 的 Chat + Persistent Canvas 范式；交互面板采用 MCP Apps 的思想但保持 Kaypal 白名单； 右侧 Canvas 是当前任务工作区和产物区，不是全局状态看板；所有真实动作继续服从本地引擎、确认队列、商业权限和证据留存规则。
