## 一、环境定位（决定修什么、怎么定级）

1. **当前产品形态**：桌面端内置后端，只监听 `127.0.0.1`。单机场景下 #1/#2/#4-9/#11 的"其他用户"**不存在**——实际可利用性低。
2. **多租户形态**：kaypal 商用前台（九场 video.vip.kaypal.cn）/ LAN 共享 / 未来云端化——此时 #1-11 全部升为高危，是**用户/租户数据隔离红线**。
3. **建议**：隔离类问题（#1-9、#11）按"多租户安全标准"修复（不赌当前形态不变）；修复成本主要是查询加 owner 过滤 + 控制器补守卫，单机零影响。

## 二、修复批次方案（按报告优先级 + 核实调整）

### 批次 A：P1 权限隔离（#1-9、#11）——先做

统一修法（一处基建，多点受益）：
- **根因**：查询/操作未按 `userId`/`tenantId`/`sessionId` 过滤 + 部分控制器仅依赖全局登录守卫。
- **基建**：抽 `OwnerScopeFilter`（复用 growth 的 `growthScopeWhere` 模式：`tenantId OR {userId, tenantId:null}`）→ 各 service 查询统一套用。
- **路径类**（#3/#4/#5）：`realpath` 校验 + 强制落点目录（素材/证据根目录）+ 会话归属前缀；拒绝 `/tmp` 直读。
- **任务归属**（#5/#6/#9）：所有 `tasks/:id` / `projects/:id` 查询带当前 user 校验 `ownerId`。
- **#10 微信支付**：先确认回调实际流向（见交底 3），若生产可打本机则补平台证书 RSA 验签（资源 `WXPAY_PLATFORM_CERT_PATH` 已预留）。
- **#8 计费**：未传 user 时拒绝或显式 4xx，不静默记主账号。

验收（每项）：负向用例——A 用户 token 查 B 用户素材/任务/项目 → 404/403；路径含 `../` 与 symlink → 403；`curl` 各一条。

### 批次 B：数据正确性（#12、#13）

- **#12**：`computeSixStageFunnel` 失败不再静默全零——升级为「接口返回部分成功 + 前端明示」或至少保留一次 console.error 可查（对齐本会话"报错不上屏=白干"教训）；深挖 tenantId:null 冲突根因后按 schema 修正。
- **#13**：定位 savings 模块当前状态（404 = 路由未挂载/模块下线），明确"可选功能未配置"提示或下线页面入口。

验收：growth 漏斗断 DB 注入 → 前端见明示而非全零；savings 接口返回确定性状态。

### 批次 C：验收可信度（#20-23）——顺手

- **#20**：扫描脚本默认 DB 改为「优先绑定运行库，缺失才回落仓库库」+ 输出标注 DB 来源（防 0/155 假红复现）。
- **#21**：billing 测试 `currentPeriodEnd` 改为相对日期生成；growth ECONNRESET 加重试或隔离。
- **#22**：已由 1.1.111 双通道发版覆盖（纠正报告过期项），下轮起以 feed 为准。
- **#23**：路由扫描加"登录态核心链路写/删/发布/读回"冒烟（与 cloud 云电脑 E2E 合并，挂账）。

### 批次 D：P2 收尾（#14-19、#24）

- **#14**：static-server 按 `API_BASE` protocol 选 `http/https.request`。
- **#15**：静态防穿透加 `realpath` 双校验。
- **#16**：限流计数→真正阻断（127.0.0.1 可宽松阈值）。
- **#17**：未登录接口收敛返回体（用户数/能力状态）。
- **#18**：可选链路（python3/uvx/osascript）出「依赖清单」文档，不承诺全内化。
- **#19**：统一为单一口径（建议以 check-release-size.js 1800/700 为准，packager.json maxSizeMB 改注释或同步）。
- **#24**：换脸页标注「引擎未配置」+ 配置指引。
