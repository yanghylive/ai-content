3010 炼刀式 AI 员工平台建设计划

目标不是嵌入炼刀闭源程序，而是在 3010 现有 AI Content / Runtime / Agent-S 体系内，自研一套可配置、可执行、可验收的本地自动化 AI 员工平台，覆盖抖音获客、微信客服、朋友圈运营、群发、视频剪辑和聚合发布。

版本2026-06-13
对象3010 AI Content 系统
参考炼刀AI员工 1.8.5 静态分析
交付形态桌面端 + 本地执行器 + 云端任务

一、结论

炼刀现在成熟的地方，不在于某一个模型，而在于把“账号、任务、素材、AI 文案、本地自动化、执行记录”串成了完整闭环。3010 要追这个能力，应该复制它的产品结构和任务链路，但不能直接依赖炼刀程序。

核心判断：代码、云端 API、打包 Python 执行器不能直接拿来用；但功能分层、页面字段、任务模型、执行器边界、验收方式可以高比例借鉴。3010 应以自研本地执行器承接平台操作，以云端任务中心承接配置和记录。

二、炼刀能力拆解

获客抖音曝光

链接曝光、搜索账号曝光、定向曝光、留资曝光。核心是读评论、筛选人群、发私信、追加评论、记录曝光结果。

微信客服自动化

读取微信会话、聊天记录和联系人，结合规则或 AI 处理新消息，适合客服接待和售后。

触达群发和加好友

群发计划、发送配置、日志、暂停恢复、重发；自动加好友计划和状态管理。

私域朋友圈运营

自动发朋友圈、随机营销、定向营销、自动点赞、固定评论和 AI 个性化评论。

内容视频剪辑

素材库、模板、一键剪辑、AI 文案、任务进度、下载结果。用于把内容生产接入营销流。

分发聚合发布

抖音、快手、小红书、视频号发布计划，支持视频/图文发布和失败状态回传。

三、3010 目标架构

层级 职责 3010 需要建设的内容
AI 员工工作台 给用户配置任务、账号、素材、文案、规则和执行开关。 新增“AI 员工”一级入口，下面分获客、客服、群发、朋友圈、剪辑、发布、记录。
云端任务中心 保存配置、调度任务、记录状态、管理额度和风控策略。 统一 task schema：任务类型、账号、计划、频控、素材、AI prompt、执行结果。
本地自动化执行器 真正控制微信、浏览器和平台页面，执行发送、评论、发布、截图。 基于现有 Runtime / Agent-S 扩展 Python/Node 执行器，提供本地 HTTP/WebSocket API。
平台适配器 每个平台独立处理授权、页面结构、发布流程、失败恢复。 Douyin、XHS、Kuaishou、VideoChannel、WeChat 五类 adapter。
证据系统 每次自动化动作可回看、可排查、可审计。 保存截图、DOM 摘要、动作日志、失败码、账号状态、平台返回提示。

四、功能范围

1. 抖音获客曝光

功能 第一版范围 验收标准
链接曝光 导入抖音视频链接，读取评论，按关键词/时间/IP/黑名单筛选，生成私信或评论。 能从真实链接读取评论，生成待执行列表，执行后回写成功/失败和截图。
搜索账号曝光 按关键词搜索账号或内容，翻阅作品，进入评论区执行筛选。 能基于关键词找到目标账号/作品，并产生有效触达对象。
定向/留资曝光 先做配置和记录模型，执行器后置。 任务可创建、可调度、可记录，执行链路进入二期。

2. 微信客服和群发

功能 第一版范围 验收标准
微信会话读取 识别本机微信登录状态，读取会话列表和最近消息。 能展示真实会话、消息时间、联系人信息；失败时给出明确原因。
AI 自动回复 按客服规则生成回复，默认先人工确认，后续开放自动发送。 回复生成可解释，发送动作有日志和截图。
群发计划 选择联系人/标签，配置文案、时间、频率、失败重试。 小批量真实发送成功，支持暂停、恢复、失败记录。
自动加好友 先做计划和执行接口，微信风控策略必须前置。 支持限速、黑名单、失败原因记录，不做无节制批量添加。

3. 朋友圈运营

功能 范围 验收标准
自动发朋友圈 图文内容、素材选择、发布时间、发布结果截图。 真实微信环境可发布一条朋友圈，并记录结果。
随机营销 随机浏览公开朋友圈，按配置点赞/评论。 执行次数、对象、内容和失败原因完整记录。
定向营销 选择联系人，进入其朋友圈主页，AI 生成个性化评论。 至少支持指定联系人列表、每日上限、AI/固定评论两种模式。

4. 视频剪辑和聚合发布

功能 范围 验收标准
素材库 上传、分类、预览、删除、空间统计。 素材能被剪辑任务和发布任务复用。
AI 文案 标题、正文、标签、平台差异化文案。 同一素材能生成不同平台文案版本。
一键剪辑 先接轻量模板剪辑，不在第一版自研复杂剪辑引擎。 输入素材和模板，输出可发布视频文件。
聚合发布 抖音、快手、小红书、视频号发布计划。 至少两个平台真实发布成功，失败原因可回看。

五、分期路线

Phase 0 1 周

技术预研和边界确认

  • 确认 3010 当前 Runtime / Agent-S 能力边界。
  • 定义统一任务模型、执行器协议、证据格式。
  • 完成抖音、微信、发布三类自动化的最小可行 spike。

验收 形成 API contract、任务 schema、执行器健康检查和三类 spike 录像/截图证据。

Phase 1 3-4 周

抖音获客 + 发布基础版

  • AI 员工工作台第一版。
  • 抖音链接曝光、搜索曝光、私信/评论文案池。
  • 抖音和小红书发布计划。
  • 执行日志、截图、失败码、每日上限。

验收 能在真实账号上跑完“导入链接 -> 筛评论 -> 生成文案 -> 执行私信/评论 -> 记录证据”的闭环。

Phase 2 4-5 周

微信客服 + 群发

  • 微信会话、联系人、聊天记录读取。
  • AI 客服回复，先人工确认后自动发送。
  • 群发计划、标签选择、频控、暂停/恢复、发送日志。
  • 自动加好友计划模型和小流量执行。

验收 一台 Windows 常用微信电脑可稳定读取会话并完成小批量发送，所有动作可追溯。

Phase 3 3-4 周

朋友圈运营

  • 自动发朋友圈。
  • 随机营销：自动浏览、点赞、固定评论。
  • 定向营销：联系人选择、AI 个性化评论。
  • 微信风控提示和账号保护策略。

验收 能完成发布、随机互动、定向互动三条真实链路，且有失败恢复和上限保护。

Phase 4 4-6 周

视频剪辑 + 全平台聚合发布

  • 素材库、AI 文案、轻量模板剪辑。
  • 抖音、快手、小红书、视频号发布 adapter。
  • 发布计划、平台差异化字段、状态回传。
  • 把剪辑结果直接接到发布计划。

验收 同一素材能生成视频和文案，并发布到至少三个平台，发布结果可回看。

七、不能直接使用炼刀程序的原因

  • 炼刀云端 API、账号体系、agentId、任务配置都绑定它自己的服务。
  • 安装包里的 Python 执行器是打包后的闭源可执行文件，不能稳定作为 3010 的可控依赖。
  • 直接复制前端代码、图片、文案和资源有版权/IP 风险。
  • 把第三方闭源执行器嵌进产品，会导致安全、升级、审计和商业交付不可控。
正确做法是“功能和工作流对标，自研实现”。页面字段、任务模型、执行证据和风控策略可以参考；底层执行器、接口和数据模型必须属于 3010。

八、关键风险

风险 影响 应对
平台风控 私信、评论、群发、发布可能失败或触发限制。 默认小流量、限速、随机等待、每日上限、失败自动停止、人工确认模式。
页面结构变化 抖音、小红书、快手、视频号页面更新会导致自动化失效。 adapter 独立、选择器版本化、截图诊断、快速热修配置。
微信兼容性 微信版本、电脑常用状态、OCR 资源都会影响稳定性。 限定支持版本，做环境检查、OCR 检查、登录状态检查和明确失败提示。
合规和账号安全 批量触达可能带来投诉和账号风险。 产品层加入频控、黑名单、敏感词、人工审核、操作审计。
视频剪辑复杂度 自研剪辑引擎成本高。 第一版只做模板剪辑和外部引擎编排，不做复杂时间线编辑器。

九、近期下一步

  1. 把 Phase 0 拆成 5 个 spike：抖音评论读取、抖音私信/评论、微信会话读取、微信发送、发布到一个平台。
  2. 补齐 3010 当前 Runtime / Agent-S 能力盘点，确认哪些已有、哪些要新增。
  3. 画 AI 员工工作台信息架构，先落“获客、客服、群发、朋友圈、剪辑、发布、记录”七个入口。
  4. 定义执行器 API：健康检查、账号状态、任务拉取、动作执行、日志回传、截图上传。
  5. 选一个真实业务场景做 Phase 1 验收：抖音爆款视频评论区获客。
