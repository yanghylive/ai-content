3010 /solutions 前端产品化干法文档

本文档用于卡住后续开发方向：/solutions 不是工程试跑页，也不是单纯页面美化； 它最终要承载 15 个方案包、64 个功能位全部接成可用产品后的用户入口。 每一轮开发必须开工前对照，结束后复盘是否跑偏。

1. 总口径

一句话： 后端按 15 个方案包 / 64 个功能位接实；前端按“用户直接使用 AI 工具和解决方案”设计，不按试跑、不按工程能力表设计。
口径 数量 前端含义
方案包总数 15 个 最终产品货架，每个方案包都要可卖、可交付、可复用。
方案包功能位 64 个 内部能力引擎，不直接暴露给普通用户。
去重功能名 57 类 可转成工具能力，但必须闭环后才能开放。
普通 RedFox API 功能位 43 个 前端只说“可用数据源”，不说 API。
SkillHub / Agent Skill 功能位 21 个 前端只说“智能处理能力”，不说 SkillHub / agent-s。
mapping 缺口 0 个 代表有映射，不代表用户侧可用。
真正缺口 执行与结果闭环 runner、日志、成本、归一化、业务对象写入、测试证据。

2. 最终三层前端结构

AI 工具层

用户：普通运营、内容、增长、客服。

展示：找热点、查账号、抓评论、改文案、查风险、生成素材。

操作：选工具 → 填输入 → 生成/分析/检查 → 保存结果。

方案包层

用户：运营负责人、老板、交付、售前。

展示：15 个解决方案包，每个都能完成一类业务结果。

操作：选方案 → 配模板 → 生成日报/报告/线索/素材。

能力诊断层

用户：管理员、工程、交付实施。

展示：64 功能位、43 API、21 SkillHub、runner、日志、失败原因。

操作：检查接入、补授权、看日志、重试失败任务。

普通用户页不展示工程诊断层。工程诊断必须单独进入管理员页面或隐藏在管理员权限后。

3. 用户页允许和禁止出现的内容

普通用户应该看到 普通用户不应该看到
找热点、查竞品、提取线索、生成内容、检查风险、保存到选题库、保存到素材库、 创建 CRM 线索、生成日报、生成报告。 43 API、21 SkillHub、功能位、runner、agent-s、redfox.skillhub.run、 mapping、试跑、dry run、单能力调试按钮。
可用、需授权、处理中、已生成、保存成功、失败原因、待确认入库。 API path、skillCode、interfaceNo、repoUrl、session id、artifact path、raw JSON。
业务对象：情报、素材、选题、内容草稿、评论洞察、CRM 线索、合规记录、报告。 RedfoxCallLog、RuntimeExecution、SolutionRunTask 内部状态直接裸露。

4. 前端开放闸门

每个功能位不能因为 mapping 存在就开放成用户工具。只有同时满足下面条件，前端才允许出现“生成 / 分析 / 检查 / 保存”按钮。

闸门 要求 不满足时前端状态
mapping 功能名、输入、输出、执行通道清楚。 不展示。
runner API 或 SkillHub 能真实执行。 显示“建设中”或仅管理员可见。
日志 有调用日志、耗时、状态、错误。 不允许商用开放。
成本 能估算和记录点数/成本。 不允许自动执行。
normalizer 结果能转成 3010 业务对象。 只能管理员诊断，不上用户页。
业务写入 能入情报、素材、选题、内容、线索、合规、报告等业务库。 只显示结果预览，不显示“保存成功”。
测试 / smoke 有自动测试或沙箱/真实验证证据。 不允许标记为可用。

5. 每轮开工前必须对照

每轮开始前必须先写下面三句话。写不清楚，不开工。
问题 必须回答 例子
本轮接哪个功能位？ 默认只能有一个编号；用户明确要求批量时，一批最多 10 个编号，且每个编号都必须来自 64 功能位矩阵。 P02-01 到 P02-05、P03-01 到 P03-03、P06-01 到 P06-02，一批 10 个。
本轮不做什么？ 明确禁止顺手改页面、改批次外功能位、扩范围。 不重构 /solutions，不接批次外功能，不开放未闭环能力。
怎么验收？ 写输入、执行通道、输出对象、入库目标、测试命令。 关键词输入 → 执行 → 归一化 → IntelligenceItem / Topic / Material。

6. 每轮结束必须复盘

复盘项 必须说明
是否跑偏 有没有改了非本轮编号？有没有提前开放未闭环功能？有没有把工程诊断放回用户页？
改了哪些文件 列文件路径，不用空泛说“优化了页面”。
输入到输出链路 写清楚从用户输入到业务对象的变化。
跑了哪些验证 guard、单测、tsc、lint、smoke、浏览器验证分别列出。
还差什么 不能说“基本好了”；必须列未闭环项。
如果复盘发现跑偏，下一轮第一件事不是继续开发，而是恢复到本干法约束。

7. /solutions 最终用户路径

步骤 用户看到 后台发生
1. 选工具或方案 找热点、查竞品、提取线索、生成内容、检查风险、15 个方案包。 选择 packageCode / toolCode。
2. 填输入 关键词、账号、作品链接、文案、平台、交付去向。 校验 inputContract，生成内部执行输入。
3. 生成 / 分析 / 检查 一个直接动作按钮，例如“生成热点选题”。 写 SolutionRun 账本，调用 API 或 SkillHub。
4. 看结果 情报、素材、选题、评论洞察、线索、合规记录、报告。 归一化并生成 SolutionResult。
5. 保存或分发 保存到选题库、素材库、创建 CRM 线索、生成日报、生成报告。 写入业务表，回填 refId 和证据链。

8. 15 个方案包前端定位

方案包 用户动作 结果落点
热点选题解决方案 生成热点选题 情报、素材、选题、内容草稿
竞品账号雷达 分析竞品账号 对标账号、增长机会、报告
评论获客解决方案 提取评论线索 评论洞察、CRM 线索、跟进任务
创作增强解决方案 生成多平台文案 文章、素材、发布草稿
发布合规解决方案 检查发布风险 合规记录、风险证据、替代表达
10 个扩展方案包 生成日报 / 报告 / 素材 / 账号体检 / 舆情监控 按闭环状态逐步开放；未闭环只显示建设中或申请开通。

9. 必跑验证

场景 命令或检查
接入数量与矩阵 node scripts/redfox-skill-integration-guard.mjs
后端功能闭环 对应 service spec、runner spec、solution spec。
前端用户页 禁止工程词；只出现直接工具动作和业务结果。
浏览器验证 打开 http://127.0.0.1:3010/solutions，按用户路径走一遍。
跑偏复盘 每轮结束必须写“是否跑偏 / 证据 / 下一轮编号”。

10. 本文档的使用方式

  1. 每轮开始前，先打开本文档，对照第 5 节。
  2. 每轮只选择一个 64 功能位编号。
  3. 后端没有闭环，前端不能开放成可用工具。
  4. 需要看 43 API / 21 SkillHub / runner / 日志时，去管理员诊断层，不污染用户页。
  5. 每轮结束，按第 6 节复盘是否跑偏。
