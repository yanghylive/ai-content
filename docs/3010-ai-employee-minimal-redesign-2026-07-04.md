# 3010 AI 员工极简化改造稿

日期：2026-07-04
对象：`http://localhost:3010`
目标：把 3010 从“企业后台功能清单”改成“小白一打开就知道让 AI 员工做什么”的产品。

## 0. 一句话结论

3010 的默认入口不要再展示 `情报中心 / 内容资产 / 发布运营 / 客户互动 / CRM / 系统配置`。

默认入口应该是：

> 今天想让哪个 AI 员工帮你做事？

小白只需要选择“发内容、找客户、回消息、看待办”。系统自动调用后面的情报、素材、生成、发布、CRM、任务、证据链。专家再进入完整模块。

## 1. 当前复杂度判断

已确认事实：

- 3010 是 KAYPAL AI 内容与运营控制台，前端默认跑在 3010，后端承接业务 API。
- 现有侧边栏直接暴露多个业务域：今日工作台、AI 任务中心、情报中心、内容资产、发布运营、增长获客、客户互动、应用与系统，CRM 安装后再插入。
- 首页一次展示统计、趋势图、GEO 任务、待发布草稿、实时运行记录，标题是“AI 工作台与监控中心”。
- 附件“炼刀AI员工”的关键启发不是 UI 精致，而是把复杂自动化包装成“AI 员工角色”，让用户先理解人设和任务，而不是理解系统模块。

复杂度根因：

1. 入口按内部功能命名，不按用户意图命名。
2. 首页像监控台，不像开工页。
3. 导航暴露了太多组织结构，小白要先学习系统。
4. 每个页面同时承担说明、表格、状态、筛选、日志、动作，主任务被稀释。
5. “执行记录、操作记录、任务运行、计划任务”语义重叠，用户不知道去哪里找结果。

## 2. 产品新定位

新定位：

> 3010 是一组可控的 AI 员工。用户说目标，AI 员工完成中间流程，高风险动作再让用户确认。

默认不讲模块，默认讲 AI 员工：

| AI 员工 | 用户心智 | 背后调用的现有能力 |
| --- | --- | --- |
| 新媒体运营员工 | 帮我发内容 | 情报、素材、选题、文章、小红书、发布检查、发布 |
| 客户互动员工 | 帮我回客户 | 评论、私信、企微、回复规则、客户档案 |
| 增长获客员工 | 帮我找客户 | 达人筛选、竞品账号、低粉爆款、线索池、CRM |
| 今日值班员工 | 告诉我今天要处理什么 | 待确认、失败修复、运行中、证据、待发布 |

## 3. 小白模式信息架构

小白模式只保留 6 个入口。

| 入口 | 页面目标 | 首屏主动作 | 隐藏到高级里的东西 |
| --- | --- | --- | --- |
| 今日 | 今天该处理什么 | 继续处理 | 实时日志、趋势图、系统指标 |
| 新建内容 | 生成第一条可发布内容 | 生成第一版 | 模型、模板参数、采集源细节 |
| 素材库 | 找到可用素材和选题 | 选择素材继续创作 | 表格批量、分页、外部源 URL |
| 发布互动 | 发布内容或处理消息 | 预检并继续 | 平台账号日志、发布任务明细 |
| 待我处理 | 统一处理确认和失败 | 确认 / 修复 | 原始错误栈、执行 JSON |
| 结果复盘 | 查看产出和证据 | 查看结果 | 全量审计日志、调试信息 |

主路径：

```text
今日
  -> 新建内容
  -> 素材 / 选题
  -> 生成草稿
  -> 发布前检查
  -> 发布 / 互动
  -> 待我处理
  -> 结果复盘
```

用户不需要知道“情报中心”“内容资产”“任务中心”这些内部模块名。

## 4. 专家模式信息架构

专家模式保留完整能力，但重新归类。

| 专家入口 | 收纳内容 |
| --- | --- |
| 今日 | 今日待办、运行概况、业务健康 |
| 市场情报 | 搜索研究、热点选题、行业情报、竞品账号、爆款拆解、品牌舆情、报告中心 |
| 内容生产 | 素材提取、知识库、选题库、创作台、小红书、视频工坊、平台改写、模板、品牌风格 |
| 发布与互动 | 发布工作台、图文发布、视频发布、平台账号、发布风险检查、统一收件箱、评论、私信、回复规则 |
| 任务与证据 | 待我确认、执行中、历史任务、证据库、计划 |
| 增长 / CRM | 线索池、达人筛选、账号体检、增长报表、客户与机会、成交助手 |
| 系统 | 应用市场、平台授权、成员权限、AI 能力、权限与安全、系统配置、本机执行器 |

## 5. 6 个小白页面线框说明

### 5.1 今日

页面标题：

```text
今天需要你处理的事
```

首屏只显示 4 类队列：

- 需要确认：真实发布、客户触达、删除、扣费、远程执行。
- 失败待修复：账号失效、素材缺失、服务断开、发布失败。
- 可继续任务：已经有草稿、素材、计划但未完成。
- 今日建议：系统根据数据推荐“先做哪一件”。

主按钮：

```text
继续处理
```

不放趋势图，不放实时运行记录。趋势图进入“结果复盘”，运行记录进入专家模式。

### 5.2 新建内容

页面标题：

```text
让 AI 员工先做出第一版
```

首屏三步：

1. 选择目标：小红书笔记、公众号文章、短视频脚本、多平台改写、客户回复。
2. 输入素材：粘贴内容、上传文件、输入链接、从素材库选。
3. 生成计划：系统用一句话说明将做什么。

默认目标：

```text
生成小红书笔记
```

生成前确认文案：

```text
我会先整理素材，再生成 3 个标题和 1 篇正文，最后给出发布前检查建议。不会自动发布。
```

主按钮：

```text
生成第一版
```

### 5.3 素材库

页面标题：

```text
选择一份素材继续做内容
```

默认展示：

- 最近可用素材
- 高分选题
- 待发布草稿
- 推荐下一步

表格筛选、每页显示、批量选择默认隐藏到：

```text
管理素材
```

### 5.4 发布互动

页面标题：

```text
发布前先确认账号、内容和风险
```

默认流程：

1. 选择正式稿。
2. 选择平台账号。
3. 自动做发布前检查。
4. 生成确认卡。
5. 用户确认后执行。

真实发布、自动回复、私信、评论都必须走同一张确认卡：

```text
将要做什么
发给谁 / 发到哪里
使用哪个账号
能否撤回
证据保存在哪里
```

### 5.5 待我处理

页面标题：

```text
这些动作需要你点头
```

队列分 3 类：

- 待确认：能继续执行。
- 需补充：缺账号、素材、权限、目标。
- 失败修复：可重试或回到来源。

按钮只保留：

```text
确认执行
去修复
忽略
```

错误不展示技术栈，先讲人话：

```text
抖音账号已失效，请重新登录后再发布。
```

技术详情进入“展开详情”。

### 5.6 结果复盘

页面标题：

```text
刚才 AI 员工完成了什么
```

默认展示：

- 最终产物：文章、回复、发布结果、线索、报告。
- 关键证据：截图、执行时间、使用账号、确认人。
- 下一步：继续优化、再次发布、沉淀客户、导出报告。

不默认展示全量日志。全量日志进入专家模式。

- 原始 task id
- RedFox / GEO 技术术语，除非用户进入专家模式

## 8. 页面模板规则

所有小白页都用同一个模板。

```text
页面标题：用户要完成的任务
一句说明：系统会帮你做什么，不会自动做什么
主动作：一个清楚按钮
当前对象：素材 / 草稿 / 客户 / 发布任务
下一步：系统推荐 1 到 3 个动作
高级：表格、筛选、日志、参数、模型、证据详情
```

按钮文案原则：

- 用动作，不用模块名。
- 用“生成第一版”，不用“内容生成”。
- 用“发布前检查”，不用“合规中心”。
- 用“确认执行”，不用“任务审批”。
- 用“查看证据”，不用“操作记录”。

## 9. 实施阶段

### 第 1 阶段：只改入口，不动业务逻辑

文件范围：

- `ai-content/frontend/src/app/(dashboard)/sidebar-items.tsx`
- `ai-content/frontend/src/app/(dashboard)/page.tsx`
- 可新增首页子组件

目标：

- 增加小白 / 专家模式切换。
- 首页改为 AI 员工大厅。
- 原监控内容进入专家抽屉。

验收：

- 小白首屏能在 5 秒内理解“发内容、找客户、回消息、看待办”。
- 不登录外部平台也能生成第一版草稿。
- 所有旧路由仍可访问。

### 第 2 阶段：改 6 个小白页面

文件范围：

- 今日
- 新建内容
- 素材库
- 发布互动
- 待我处理
- 结果复盘

目标：

- 每页只有一个主任务。
- 高级配置进入抽屉。
- 高风险动作统一确认卡。

### 第 3 阶段：专家模式收口

目标：

- 专家模式保留完整能力。
- 所有旧入口进入 canonical route map。
- 设置、本机执行器、模型、权限、日志统一归到系统。

## 10. 关键体验指标

上线后只看这些指标：

| 指标 | 目标 |
| --- | --- |
| 首次打开到点击首个主动作 | 小于 30 秒 |
| 首次生成可编辑草稿 | 小于 5 分钟 |
| 小白首屏可见主入口数量 | 不超过 6 个 |
| 每页主按钮数量 | 1 个 |
| 高风险动作误执行 | 0 |
| 失败后可恢复率 | 90% 以上 |

## 11. 不建议做的事

- 不要继续新增一级导航。
- 不要把“多模态”“Agent”“RedFox”“执行器”放给小白看。
- 不要用教程弥补复杂界面。
- 不要把日志、趋势、表格默认放首屏。
- 不要照搬附件里的平台风控规避能力。只借鉴“AI 员工角色化”和“输入需求”。

## 12. 最终产品感

用户打开 3010 后应该感觉：

> 我不用懂这个系统。  
> 我只要说想做什么。  
> AI 员工会先做一版。  
> 真要发出去或影响客户时，它会停下来问我。  
> 做完以后我能看到结果和证据。

这就是 3010 应该追求的苹果式极简：不是少功能，而是让复杂功能只在需要时出现。
