Agent 操作驾驶台开发任务拆解

本文把立项方案拆成可执行开发任务包，便于按 Sprint 推进。返回 立项书目录。

1. 总体里程碑

里程碑周期目标交付物
M1 信息架构W1确认三栏布局、状态模型、Surface 白名单。UI skeleton、类型草案、路由保持可用。
M2 可用驾驶台W2-W3实现 Chat + 任务草稿 + 当前任务工作区 + 创建任务。AgentCockpitPage MVP。
M3 治理闭环W4-W5接入 blocker、confirmations、evidence。当前任务确认卡、证据卡和交付物面板。
M4 商业验收W6-W8补测试、移动端、失败恢复、旧流程兼容。验收脚本通过、发布候选。

2. Sprint 任务包

FE-01 Cockpit Layout P0

  • 新增三栏布局。
  • 保留旧 AgentConsolePage 功能入口。
  • 左栏会话分组静态版。

FE-02 Task Draft Panel P0

  • 实现 AgentTaskDraft 类型。
  • 任务类型、执行范围、平台、步骤、风险可编辑。
  • 支持 preset 生成草稿。

FE-03 Surface Renderer P0

  • 实现 task_draft、approval_panel、evidence_list。
  • 非法 surface 降级。
  • action 映射到本地 handler。

BE-01 API Contract Compatibility P0

  • createAgentSession 接收可选 taskDraft。
  • session metadata 保存草稿摘要。
  • 旧请求保持不变。

FE-04 Current Task Canvas P1

  • 把当前 session events 投影为任务步骤、证据卡、失败原因和产物。
  • 右栏显示当前任务工作区，不显示全局状态数字。
  • 支持当前任务证据导出。

FE-05 Confirmation Surface P1

  • 当前任务确认项渲染为确认卡。
  • 审批/拒绝调用原接口。
  • 风险检查项可见。

AI-01 Intent Router P1

  • 规则优先识别 chat-only、browser、file、publishing。
  • LLM 生成草稿作为增强。
  • 低置信度时要求用户补充。

QA-01 Acceptance Automation P0

  • 覆盖旧 /agent-console 可用。
  • 覆盖 blocker 和补齐动作。
  • 覆盖确认队列不能绕过。

4. 开发顺序建议

  1. 先做纯前端 Cockpit skeleton，不动后端。
  2. 把旧 AgentConsolePage create flow 嵌入新中区，保证功能不断。
  3. 抽 projection，把当前任务草稿、预览、确认、证据和产物接到右侧 Canvas。
  4. 接 blocker resolution actions，解决“只提示不帮补齐”的问题。
  5. 接当前任务 confirmations/evidence Surface；不做全局监控面板。
  6. 最后再加 LLM 任务草稿生成，不让模型链路阻塞主功能。
