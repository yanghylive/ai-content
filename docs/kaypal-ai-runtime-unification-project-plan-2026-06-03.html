Runtime 统一项目规划（单人 7×24 模式）

本规划与技术方案 kaypal-ai-runtime-unification-development-plan-2026-06-03.html 配套： 技术方案讲"做什么、怎么做"，本规划讲"怎么管、什么时候做、出问题怎么办"。

团队：单人独立开发。工时模式：7×24（无固定工时上限）。决策机制：自决。沟通节奏：无外部协调，仅自我日报。 D1 = 2026-06-03（周三），目标完成日 = 2026-06-27（周六，max 25 天）。

诚实声明：7×24 不是可持续模式。任何人持续 ≥ 2 周 14h/day 都会进入认知衰退期。 本规划按"工时弹性充裕"做范围设计，但日产出按 8-10h 稳态估，保留 30% buffer。 如果出现连续 3 天产出明显下滑，立即降到 6h/day 恢复模式 2 天，不要硬撑。

一、项目章程

业务目标

把当前 3010/3011/5409 三件套合并成 KaypalAI 内容创作平台桌面 App，让用户只用一个 App 完成抖音/视频号的发布与互动，以及微信桌面的客户互动；为后续 SaaS / 多平台扩张留出 A+ 接口。

技术目标

四件套架构成型：3010 唯一入口 + 3011 ExecutorRouter 中枢 + Local Runtime（浏览器 CDP）+ Agent-S（桌面 GUI）；统一 RuntimeExecutionResult 契约；证据全链路可追溯；5409 作为独立项目下线。

成功标准

  • 技术方案八节验收 9 项全过，证据归档。
  • 双击 App 即可启动四件套，用户不接触终端命令。
  • 抖音/视频号 4 条互动 + 微信 3 条互动各连续 5 轮真实发送 + 回读。
  • 失败链路 8 项全部不显示假成功。
  • 5409 端口在主仓内不再启动，源仓打 legacy/5409-final 归档。

范围 / 边界

  • 做：B+ 全部 + A+ 接口预留（capability-based Router、Platform 目录隔离、executorMeta 字段）。
  • 不做：S+ 任何投入（多 Agent、LLM Router、Computer Use 集成）。
  • 不做：Windows / Linux 支持，本期只覆盖 macOS。
  • 不做：新增平台（飞书 / 钉钉 / 企微）；仅保留接口可扩。
  • 不做：云端控制面；保持单机本地。

关键假设

  • Agent-S 现状可用，微信桌面执行链路本期不阻塞。
  • 5409 仓库可访问，CDP 代码可逐模块迁移。
  • macOS 测试机 + 至少 1 个抖音、1 个视频号、1 个微信测试账号可用。
  • 开发者在 P1-P5 期间无重大私事中断 ≥ 1 周。
  • Anthropic / OpenAI Computer Use 本期内不发生颠覆性进展导致本方案过时。

利益相关方

  • 当前：开发者本人（既是产品、研发、QA、运维）。
  • 未来 90 天：早期客户（1-3 个内部或熟人灰度账号）。
  • 未来 6 个月：第一个外部协作者（前端 / QA / 运营），他们要能读懂仓库进入工作——这决定了 ADR 和 PROGRESS.md 的质量。

四、单人纪律（替代团队流程）

单人项目最大的敌人不是工时，是判断力衰退和上下文丢失。下面这套纪律不是"建议"，是 P0 流程，缺一不可。

每日 Routine

  • 晨 15-30 分钟：打开 PROGRESS.md，写今日 TODO（≤ 3 件主任务）；扫一眼 ADR 列表和 backlog。
  • 工作段：WIP=1，一次只做一件主任务；中断后回到 PROGRESS.md 续上。
  • 每 90 分钟：起来走 5 分钟。强制。
  • 晚 15-30 分钟：commit + push（即便只有半成品）；PROGRESS.md 写今日完成 / 卡点 / 明日计划。
  • 睡前：不再写代码。睡眠债是 burnout 第一来源。

阶段 Gate（自审）

  • 每个 P 结束前，对照表 Gate 列逐项打勾。打不勾不能进下一阶段，哪怕只差最后一个验证。
  • Gate 通过后，写一份 Retrospective：本阶段超时项、技术债、待优化点，入 backlog。
  • 不允许"先进下阶段，回头补"。"回头"永远不会回头。
