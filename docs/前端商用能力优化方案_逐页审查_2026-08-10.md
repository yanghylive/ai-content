# 前端商用能力优化方案——逐页审查

> 2026-08-10 · 逐页审查约 50 个核心商用路由 · 以"用户能否完成商用任务"为标尺

---

## 一、严重问题 Top 10（按商用影响排序）

### 🔴 P0 · 直接阻断商用流程（必须修）

**1. `commercial-readiness` 空壳页**
- 问题：只渲染 2 个统计数字，「处理待完善项」点击后链回自身 `?filter=pending`，页面不消费该参数，无检查清单/可操作项
- 影响：上线前自查流程完全卡死
- 方案：用 real API 重写——拉取 redfox 连接/平台账号/模型配置/合规/额度 5 维度检查项，每项可操作（跳转对应设置页），`?filter=pending` 过滤未就绪项

**2. `content/video` 死路由占位**
- 问题：内容域「视频」分类入口指向 UnderConstruction 占位
- 影响：用户从 content 页点「视频」看到"建设中"
- 方案：改为转发 `/video-studio`（redirect）或直接渲染 video-studio 内容

**3. `savings/wallet`、`savings/orders` 路由 404**
- 问题：只是 savings 内 Tab，无独立路由，外部深链 404
- 方案：加 `savings/wallet/page.tsx` 和 `savings/orders/page.tsx`，各 redirect 到 `/savings?tab=wallet|orders`（或渲染 SavingsShell 带初始 tab）

**4. CRM v2 主操作逃逸到 legacy**
- 问题：crm-center(v2)「新增/导出客户」→ `/crm?action=new` → HybridRoute 规则带参→legacy → 用户跳出 v2
- 方案：在 crm-center v2 内嵌新建表单 Modal（不跳 legacy），导出走独立 Modal 或 /crm-import-v2

**5. `boss-recruit` 账号绑定高摩擦**
- 问题：要求用户手粘 storageState JSON，普通客户无法独立完成
- 方案：(a) 加图文引导截图（DevTools → Application → 导出步骤）；(b) 未来支持扫码登录自动获取（需后端配合）；(c) 候选人列表用 API 拉取替代手填名称

### 🟡 P1 · 移动端体验断崖

**6. 复杂操作台缺移动端降级拦截**
- 页面：`video-studio`、`engagement/douyin-comments`、`engagement/wechat`、`engagement`（v2）
- 问题：无 isMobile 分支，手机进入看到挤压桌面 UI
- 方案：加移动端拦截组件——检测 UA/isMobile 后显示「该功能需在电脑端使用」+ 引导返回（复用 mobile-capabilities 页话术），不做半残移动视图

**7. 微信生态能力大面积"暂不支持"**
- 页面：wechat-groups / wechat-moments / workbench/wechat-v2/mass-send / moments-publish / moments-marketing
- 问题：微信群发/朋友圈发布是高频商用需求，全是占位
- 方案：标为「路线图」项——需微信桌面客户端 RPA 能力落地（C2 依赖），当前在 mobile-capabilities 页已声明边界，建议这些页统一改为「能力路线图」说明页（而非 UnderConstruction 空壳）

### 🟢 P2 · 信息架构与体验

**8. `poi` 删除无二次确认**
- 方案：`handleDelete` 加 `window.confirm("确定删除门店「{name}」？此操作不可撤销")`

**9. 路由冗余**
- `sessions` = `tasks/runs`（完全重复）→ sessions 加 redirect 到 tasks/runs
- `confirmations` = `tasks/confirmations` → confirmations 加 redirect
- CRM 三详情入口 → 统一到 `/crm/detail/:id`，旧路径 redirect

**10. 内容域新旧混杂**
- `content/topics` → 旧版转发；`content/knowledge` → 只剩 redirect；`content/video` → 占位
- 方案：统一用 routeAliases 把旧路径归一到新路径（content/topics → /content/articles?type=topic 等），或逐个迁移到 HybridRoute v2

## 三、实施方案（3 批）

### 批次 1 · 商用断链修复（P0，2-3h）✅ 已落地 2026-08-10
1. ✅ commercial-readiness 重写（真实检查清单）——v2 center 消费 `GET /commercial-readiness/summary`，渲染 16 项真实 checks（pass/warn/blocker），每项映射对应设置页操作链接，`?filter=pending`/`?filter=done` 过滤生效
2. ✅ content/video redirect → /video-studio（服务端 redirect，替代 UnderConstruction 占位）
3. ✅ savings/wallet + savings/orders 加独立路由页（SavingsShell initialTab prop），深链不再 404
4. ✅ CRM v2 内嵌新建表单 Modal（`components/v2/crm-customer-form.tsx`，同页创建不跳 legacy）；导出改为列表头部「导出 CSV」客户端生成；advancedLinks 移除逃逸 legacy 的 export 死链
5. ✅ boss-recruit 降摩擦——上传卡加 5 步图文引导（含无 Export 选项时的替代导出法）；打招呼候选人改下拉选择（API 拉取）+ 手填兜底；移动端同版适配；扫码登录标注为路线图
6. ✅ poi 删除加 `window.confirm` 二次确认；sessions → redirect /tasks/runs；confirmations → redirect /tasks/confirmations

### 批次 2 · 移动端降级拦截（P1，1-2h）✅ 已落地 2026-08-10
7. ✅ 4 个复杂操作台加移动拦截组件（新增 `components/v2/desktop-only-gate.tsx`）——video-studio / engagement / engagement/douyin-comments / engagement/wechat：移动端显示「需在电脑端使用」拦截页（含手机端可做什么提示 + 双按钮引导），桌面端正常渲染不受影响
8. ✅ 微信生态占位页统一改为「能力路线图」说明（新增 `components/v2/feature-roadmap.tsx`）——wechat-groups / wechat-moments / wechat-v2/mass-send / moments-publish / moments-marketing：5 页从 UnderConstruction 空壳改为「当前状态 + 预计时间 + 为什么暂无 + 现在可以先做」四段式说明，讲清 C2 RPA 依赖与替代方案

### 批次 3 · 信息架构清理（P2，1h）✅ 已落地 2026-08-10
9. ✅ CRM 三详情入口统一——客户详情统一到 `/crm/customer?id=`（CustomerDetailClient 新完整档案，含欢迎语面板）；crm-center / channel-console 跳转改指新入口；`/crm/detail?id=` 旧路由保留为客户端 redirect（带参跳转，历史深链/书签不失效）
10. ✅ content 域旧路由归一——**修复 `/knowledge-base` 重定向循环**（routeAliases 曾把 /knowledge-base alias 到 /content/knowledge，而后者 redirect 回 /knowledge-base，构成无限循环）；content/topics/strategies/templates/styles 确认 re-export 顶层 v2 页（等价迁移，无断链）；content/video 已在批次 1 处理

三个批次全部落地：P0 断链（6 项）→ P1 移动降级（2 项）→ P2 信息架构（2 项），实测 25/25（8+11+6）。
