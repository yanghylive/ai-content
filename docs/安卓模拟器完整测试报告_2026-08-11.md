## 一、环境修复（本轮测试发现并解决的关键问题）

**症状**：首次跑测试 22 项几乎全挂 —— 所有页面渲染 "Skip to content / 正在检查登录状态..." 后被踢到 `/login?next=...`，但 curl 带同一 cookie 访问 `/api/auth/me` 返回 200。

**根因**：`frontend/.env.local`（未追踪）设 `NEXT_PUBLIC_API_BASE=http://localhost:3011/api`，被内联进构建产物 JS。**桌面浏览器里 localhost 是宿主机没问题；模拟器里 localhost 指向设备自身** → 前端所有 API 请求失败 → 登录守卫 `authApi.me()` 超时 → 跳登录。

**修复**：
1. 临时挪开 `.env.local`（`mv .env.local /tmp/`，构建后已恢复）
2. 重新构建：`NEXT_PUBLIC_API_BASE=http://10.0.2.2:3421/api`（10.0.2.2 = 模拟器访问宿主机的地址，走静态服务器 3421 的 /api 代理）
3. 验证产物中 API 基址已更新（`grep -rho "10.0.2.2" out/_next/static/chunks/*.js` 命中）

**教训（重要）**：模拟器测试产物（10.0.2.2）与桌面测试产物（localhost）互斥，构建前必须确认 API base 匹配目标环境。`.env.local` 优先级高于命令行 NEXT_PUBLIC_API_BASE，构建前必须临时挪开。
