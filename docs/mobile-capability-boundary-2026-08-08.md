# JIUZHANG AI 安卓端能力边界（产品文档）

> 版本：2026-08-08 ｜ 关联：A1 `/mobile-capabilities` 页面、PRD 对照 §7、用户任务矩阵（08-05）
> 目的：明确手机端「可独立完成 vs 需桌面端」的产品边界，消除用户认知错位（用户误以为手机端全能）。

---

## 一、一句话边界

**手机端 = 运营指挥台**（看、批、改、查、确认）；**桌面端 = 执行引擎**（自动发布、微信自动化、扫码授权、本地 Bridge）。

## 二、手机端可独立完成（✅ 5 项核心能力）

| 能力 | 入口 | 说明 |
|---|---|---|
| **查看** | 今天/内容/发布/消息/我的 5 tab + 全部子页 | 全量业务数据只读 |
| **审批** | `/tasks/confirmations` 待我确认 | 每条「确认发送」，人工闸门在手机端完成 |
| **轻编辑** | `/content/workspace` 内容工作区 | 新建/写文章/继续草稿/素材库/文案改写 |
| **任务监控** | 发布页（待确认/排队中/今日已发/失败统计） | 任务列表 + 去确认 + 查看失败 + 重试入口 |
| **结果查看** | 发布结果回读 | 成功/失败/待回执 + 失败原因 + 重试 |

补充可独立完成：账号密码登录、视频去水印（链接采集）、AI 生图/配音、多账号矩阵查看、消息 4 渠道 + AI 客服、发布包「去 App 发布」平台感知跳转。

## 三、手机端**不可**独立完成（⛔ 必须桌面端）

| 能力 | 原因 | 桌面端路径 |
|---|---|---|
| **自动发布** | 发布执行依赖本地 Bridge 与目标平台会话，手机端只做「确认/监控」；"手机端不自动发布"是设计如此 | 桌面端发布中心执行 |
| **微信互动**（联系人/群定位、发送） | 依赖桌面微信自动化（macOS 窗口读取 / DB 读取）；手机端无入口 | 桌面端微信工作台 |
| **微信群发/朋友圈** | **已下线（2026-08-09）**：触发微信平台风控可能封号，前端所有入口已移除 | 无（不支持） |
| **重新扫码 / 账号授权** | 扫码依赖桌面浏览器引擎（本地 Browser Runtime） | 桌面端多账号矩阵 |
| **重发布** | 同自动发布：执行链路在桌面 | 桌面端失败任务重试 |

## 四、决策记录

- 视频工作坊 / 换脸：前端入口隐藏（排除本轮），手机端不可见。
- 抖音深度互动（搜索/定向/链接曝光）：主要差距，立项评估中（D3）。
- 微信群发/朋友圈：**已下线（2026-08-09）**——合规评估结论：触发微信平台风控可能封号；前端侧边栏/任务中心/工作台入口全部移除，7 个相关路由改「暂不支持」提示页。详见 `docs/d-batch-evaluation-2026-08-09.md`。

## 五、验收口径（与 A1 页面一致）

- 页面/文档文案覆盖上表全部边界，**无夸大承诺**（不宣称手机端可自动发布/微信自动化）。
- 手机端任何「需桌面」能力入口处有明确引导（如矩阵页「请在电脑端打开 JIUZHANG AI 重新扫码」）。
