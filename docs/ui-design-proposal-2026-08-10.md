# JIUZHANG AI 工作台 UI 设计方案 v1.0

日期：2026-08-10 · 角色：UI Designer · 基线：frontend（HeroUI + Tailwind + kaypal-v3 双主题令牌）

## 一、现状诊断（基于截图与代码盘点）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | 导航平铺无层级 | layout 侧栏 10 个图标并列，无分组标题 | 新用户不知从哪开始，功能越多越迷路 |
| 2 | 首页是"通知板"不是"工作台" | 问候语占最大字号；三张入口卡是空链接；通知条文案截断 | 打开页面无法直接干活 |
| 3 | 数据无上下文 | 4 个指标卡纯数字（0/29），无趋势无单位无动作 | 数字不构成决策 |
| 4 | 徽章只施压不解决 | 侧栏红点 13/29，点进去仍是列表，无批量处理 | 焦虑感而非效率 |
| 5 | 组件样式分叉 | v3 令牌仅 133 处引用，各页仍有硬编码颜色 | 视觉一致性债 |

已有资产（保留）：kaypal-v3 双主题色板（品牌玫红 + 强调紫 + 语义色）、圆角卡片语言、HeroUI 组件库、暗色模式。

## 二、设计原则

1. **任务导向**：导航与首页按"获客→内容→互动→管理"工作流组织，不按技术模块。
2. **数据要可行动**：任何数字必须带趋势或动作入口；纯展示数字不占首屏。
3. **一致性优先**：新组件一律引用 CSS 变量，禁止硬编码颜色/圆角/间距。
4. **无障碍底线**：WCAG AA（正文对比 ≥4.5:1、键盘可达、focus 可见、动效可关闭）。

## 三、设计令牌使用约定（不新增色板，统一用法）

| 用途 | 令牌 | 说明 |
|---|---|---|
| 品牌/主操作 | `--kaypal-v3-accent`（#7c5cf0 / 暗 #8b6ff5） | 主按钮、当前导航、链接 |
| 成功/增长 | `--kaypal-v3-*` teal 族 | 趋势上升、完成态 |
| 警告 | amber 族 | 待确认、需关注 |
| 危险 | danger 族 | 失败任务、删除 |
| 画布/卡面 | `canvas` / 卡面变量 | 页底 + 卡片分层 |
| 圆角 | 卡 12px / 控件 8px / 徽章头像 full | 全产品统一 |
| 间距 | 4px 基准：8/12/16/24/32 | 区块 24、卡内 12-16 |
| 字号 | 页标题 20 / 卡标题 14(500) / 正文 13 / 辅助 12 | 两档字重 400/500 |

## 四、信息架构（导航分组）

| 分组 | 包含页（现有路由归并） | 设计意图 |
|---|---|---|
| 获客 | 客户线索、门店 POI、曝光增长 | 工作流第一步， teal 色标 |
| 内容 | 今天（首页）、AI 创作、素材库、商品视频 | 核心生产力，紫色标 |
| 互动 | 发布矩阵、群发、私信回访、待确认回复 | 对外触达，蓝色标 |
| 管理 | 账号、用量成本、设置 | 低频收底，灰色标 |

侧栏形态：桌面 = 分组标题 + 文字项 + 色点；移动 = 保留图标栏但按组着色 + 底部"更多"收纳管理组。

## 五、首页（今天）规格

布局自上而下：

1. **命令栏**（⌘K）：一句话输入任务，AI 直达任意功能——取代大搜索框和三个空入口卡。
2. **指标卡组**（4 卡）：数字 + 较昨日/本周趋势 + 语义色；点击卡跳对应列表（带筛选）。
3. **待处理清单**：每条 = 语义图标 + 标题 + 一句原因 + 单个主操作（批量重试/去确认/去处理）。上限 5 条，溢出收"查看全部"。
4. **今日工作流条**：采集→生成→确认→查看 四步，标记完成/进行中，并显示 AI 的下一步建议（如"已草拟 3 篇图文"）。

问候语降为页眉一行小字，不再占视觉中心。

## 六、组件规范要点

- 按钮三档：主（品牌紫底白字）/ 次（描边）/ 幽灵；桌面高 32、移动端触区 ≥44。
- 徽章语义：红=需要你处理；紫=中性计数；不出现无动作红点。
- 空状态：占位图形 + 一句引导 + 一个动作按钮；禁止纯"0"展示。
- 加载：列表骨架屏；禁止整页 spinner。
- 通知：toast 右上、可堆叠、5s 自动退；重要失败进待处理清单而非 toast。

## 七、无障碍清单

- 正文对比 ≥4.5:1（现有 v3 文本色在双主题下已达标，新增硬编码需校验）。
- 全部交互可 Tab 到达，focus ring 用 accent 2px offset。
- 图标按钮必带 aria-label；徽章数字对读屏提供"29 条待确认"完整文案。
- `prefers-reduced-motion` 下关闭位移动画。

## 八、实施路线

| 优先级 | 内容 | 预估 |
|---|---|---|
