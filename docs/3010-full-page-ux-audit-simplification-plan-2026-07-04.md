# 3010 全功能页体验评估与简化方案

日期：2026-07-04
对象：`http://localhost:3010`
范围：`ai-content/frontend/src/app/(dashboard)` 全部功能页
状态：先出方案，不改生产代码

## 0. 这次怎么评估

本轮不先讨论导航样式，也不先做新线框。

我把问题拆成 6 个专家视角并行评估：

1. 信息架构：路由、侧边栏、旧入口、新入口、业务域归属。
2. 单页操作逻辑：每页是否有明确主任务，是否一页塞多个对象。
3. 跨页流程：从发现、创作、发布、确认、留痕、复盘是否闭环。
4. 二级导航与命名：同义词、错位词、内部术语、小白可懂性。
5. 全球竞品：AI 工作台、自动化、内容运营、CRM、客服产品的新手简化方式。
6. 新手上手与空状态：说明页、空壳页、跳转页、安装/连接页如何处理。

已确认：

- 代码层全量检查了 `129` 个 dashboard `page.tsx`。
- 浏览器验证了关键入口和高风险页：`/`、`/solutions`、`/content`、`/materials`、`/distribution`、`/distribution/compliance`、`/tasks`、`/tasks/confirmations`、`/tasks/evidence`、`/engagement`、`/workbench/douyin-comments`、`/growth`、`/crm`、`/admin`、`/war-room`、`/capabilities/tools`。
- 没有修改生产代码。

## 1. 总判断

3010 现在不是简单的“导航太多”，而是四类复杂度叠在一起：

1. 页面功能复杂：很多页面同时承担配置、执行、记录、诊断、详情、历史。
2. 页面互相逻辑混乱：业务链路已经存在，但被旧入口、深链、记录页和说明页打散。
3. 二级导航位置与命名不稳定：侧边栏、页面横向导航、按钮文案不是同一套语言。
4. 说明页伪装成功能页：很多页面只是解释能力边界，然后跳到别处，用户会以为点错了。

所以第一阶段不要做视觉美化，也不要只重排左侧菜单。

第一阶段要做的是：

> 把 3010 从“页面集合”整理成“7 条业务链 + 1 个任务中心 + 1 个系统设置”。

## 3. 全球参考给 3010 的启发

### 3.1 自然语言先行

Microsoft Copilot Studio 支持用日常语言描述流程，系统再生成可审阅计划，并在确认后构建流程。

对 3010 的启发：

- 小白入口不要先展示模块。
- 先让用户说目标：找选题、写内容、检查发布、回复评论、导入客户。
- 系统生成计划：输入、处理、输出、是否需要确认。

来源：[Microsoft Copilot Studio natural language agent flow](https://learn.microsoft.com/en-us/microsoft-copilot-studio/flow-nl)

### 3.2 模板库降低起步成本

Make AI Agents 强调 ready-made agents / agent library，用户可以从现成场景开始，而不是从空白流程开始。

对 3010 的启发：

- `/solutions` 不应该像方案市场 + 执行台 + 历史页。
- 应变成 5 个高频任务模板：找热点选题、生成小红书、发布前检查、回复评论、导入 CRM。
- 每个模板只保留一个主按钮：开始。

来源：[Make AI Agents](https://www.make.com/en/ai-agents)、[Make Agent Library](https://www.make.com/en/ai-agents-library)

### 3.3 透明执行 + 人工门禁

Make 强调可见决策、步骤透明、人工控制；发布、外联、删除、扣费这类动作不能藏在黑盒里。

对 3010 的启发：

- 所有高风险动作统一进入 `/tasks/confirmations`。
- “待我确认”不能只是任务中心子页，它应成为所有业务链路的安全闸门。
- `/tasks/evidence` 统一叫“操作凭证”，看截图、步骤、失败原因、结果文件。

来源：[Make AI Agents](https://www.make.com/en/ai-agents)

### 3.4 一个素材，多渠道输出

HubSpot Breeze Content Remix 的模式是：一个已有内容，选择多个输出格式，生成后在预览面板审阅，再保存到对应工具。

对 3010 的启发：

- `/content/optimization`、`/content/articles`、`/content/xiaohongshu`、`/video-workshop` 不应割裂。
- 新手只需要“输入素材 -> 选择输出 -> 预览编辑 -> 送发布前检查”。
- 高级模板、品牌风格、平台参数后置。

来源：[HubSpot Breeze Content Remix](https://www.hubspot.com/products/artificial-intelligence/use-cases/tailor-content-for-channels)

### 3.5 工作区内即时改，不跳工具页

Canva AI 的核心体验是用户在当前工作区直接生成、改写、设计，而不是跳到多个工具页面。

对 3010 的启发：

- 结果页直接提供快捷动作：更像小红书、缩短、换标题、生成封面、送发布检查。
- 不要让用户从“草稿”跳到“多平台文案”再跳到“发布风险检查”再跳到“发布运营”。

来源：[Canva AI](https://www.canva.com/canva-ai/)

### 3.6 知识导入而不是规则手写

Intercom Fin 和 Zendesk AI Agents 都把内容/知识作为 AI 处理客户问题的基础。

对 3010 的启发：

- `/knowledge-base` 要从“知识库管理”改成“把资料交给 AI 使用”。
- 小白只看到：粘贴资料、上传文件、从素材转知识、测试能不能搜到。
- 同步、解析、云端、本机这些细节进专家区。

来源：[Intercom Fin content](https://www.intercom.com/help/en/articles/7837514-add-your-content-for-fin-ai-agent)、[Zendesk AI Agents](https://www.zendesk.com/service/ai/ai-agents/)

### 3.7 苹果式极简原则

Apple HIG 的方向可转译为：

- 用普通语言，不用内部术语。
- 只在需要时显示高级能力。
- 让用户先完成一个动作，再学习更多能力。
- 导航服务内容，而不是展示组织结构。

对 3010 的启发：

- 首屏不放全量图表、日志、技术状态。
- 每页只给一个主任务。
- 高级筛选、日志、JSON、调试信息默认折叠。

来源：[Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines)、[Apple HIG Writing](https://developer.apple.com/design/human-interface-guidelines/writing)、[Apple HIG Onboarding](https://developer.apple.com/design/human-interface-guidelines/onboarding)

## 4. 简化后的产品骨架

### 4.1 小白可见入口

不要超过 6 个：

1. 今日：今天要处理什么。
2. 找机会：热点、线索、竞品、评论洞察。
3. 做内容：素材、知识、选题、草稿、多平台改写。
4. 发布确认：发布检查、发布队列、待我确认。
5. 客户跟进：评论、私信、线索、CRM 跟进。
6. 设置：账号、平台、AI 服务、运行环境。

### 4.2 专家入口

专家模式保留完整能力，但不再把旧路由、深链、说明页当一级能力：

1. 情报与线索
2. 内容生产
3. 发布与互动
4. 客户与增长
5. 任务与凭证
6. 系统与连接

### 4.3 真实业务链

内容链：

```text
找机会
  -> 选题
  -> 做内容
  -> 发布前检查
  -> 发布队列
  -> 待我确认
  -> 操作凭证
  -> 任务历史
```

客户链：

```text
互动消息
  -> 回复建议
  -> 待我确认
  -> 线索入池
  -> CRM 客户
  -> 成交助手
  -> 跟进记录
```

系统链：

```text
账号与设备
  -> 平台账号
  -> AI 服务
  -> 运行环境检查
  -> 风控设置
```

## 5. 单页操作逻辑规则

每个页面必须通过这 6 条检查：

1. 页面只能有一个主任务。
2. 首屏必须有一个主按钮，不能超过两个次按钮。
3. 页面名必须说用户要做什么，不说内部模块。
4. 表格、筛选、批量、日志默认不是首屏主角。
5. 结果必须留在当前页可继续处理，不要马上跳工具页。
6. 空状态必须给下一步按钮，不只写“暂无”。

标准页面结构：

```text
页面标题：我要完成什么
一句话说明：完成后会得到什么
主操作：开始 / 继续 / 检查 / 确认
当前对象：素材 / 内容 / 客户 / 任务
结果区：草稿 / 检查结果 / 回复建议 / 导入预览
下一步：送检查 / 发布 / 待确认 / 保存
高级：筛选、日志、原始数据、调试信息
```

## 6. 页面级改造方案

### 6.1 `/solutions`

当前：方案市场 + 执行台 + 历史结果。

改成：

- 页面名：开始一个任务
- 首屏只放 5 个任务模板。
- 点击模板后进入一句话输入。
- 生成计划后再显示执行步骤。
- 历史结果移到任务历史。
- 建设中模板不出现在主列表，放专家/实验区。

### 6.2 `/distribution`

当前：发布任务、图文、视频、账号、素材、日志同页。

改成：

- 页面名：发布内容
- 首屏只做“创建一次发布任务”。
- 第一步选择内容，第二步选择账号，第三步发布前检查，第四步提交待确认。
- 账号管理、素材管理、发布结果收进二级页或高级抽屉。
- “发布任务”改名“发布队列”。
- “发布记录/运行记录”改名“发布结果”，不再混用任务中心词。

### 6.3 `/tasks`

当前：任务中心试图收束，但命名太多。

改成：

- 页面名：任务中心
- 二级固定为：待我确认、正在运行、任务历史、操作凭证、定时任务。
- 删除或隐藏：运行总览、任务运行、执行记录、操作记录这些同义词。
- 首页卡片只显示数量和主动作。

### 6.4 `/tasks/evidence`

当前：风险记录、任务过程、截图、文件、审计都堆一起。

改成：

- 页面名：操作凭证
- 默认按任务聚合，不按证据类型堆表。
- 用户先看到“哪件事、结果、是否有风险、证据是否完整”。
- 原始截图、日志、文件放详情抽屉。

### 6.5 `/materials` / `/content`

当前：素材表格是主角，旧入口和新入口并存。

改成：

- 统一入口：`/content/materials` 或 `/content` 内部 tab，旧 `/materials` 只兼容跳转。
- 页面名：选择素材
- 首屏显示最近素材、高分素材、待处理素材。
- 批量删除、分页、采集源、原文链接进“管理素材”。

### 6.6 `/knowledge-base`

当前：写文本、上传、检索、本机库、同步同屏。

改成：

- 页面名：把资料交给 AI
- 首屏三块：粘贴资料、上传文件、从素材转知识。
- 检索验证作为保存后的下一步。
- 同步云端、本机状态、解析详情进专家抽屉。

### 6.7 `/engagement`

当前：自动发送默认暴露，旧 workbench / interaction 路由并存。

改成：

- 统一可见入口：`/engagement/*`
- 默认模式从“自动发送”改成“确认后发送”。
- 首屏主任务：处理今天的评论/私信。
- 回复规则、客户档案、互动记录作为后置。
- 旧 `/workbench/*`、`/interaction/*` 不再出现在按钮和面包屑里。

### 6.8 `/crm`

当前：联系人、公司、商机、任务、备注五套对象同屏。

改成：

- 页面名：客户跟进
- 首屏只显示“今天该跟进的人”和“客户详情”。
- 公司、商机、任务、备注作为客户详情里的分段，而不是首屏并列 tab。
- 快速新增只保留“新增客户”，其他对象进高级。

### 6.9 系统类页面

当前：`/admin`、`/apps`、`/capabilities`、`/settings`、`/platforms` 分裂。

改成统一“设置”：

1. 账号与设备
2. 平台账号
3. AI 服务
4. 数据来源
5. 运行环境检查
6. 风控设置
7. 应用与安装

说明页全部降级为卡片，不再作为主路径页面。

## 8. 二级导航位置规则

1. 侧边栏只放业务域，不放 `?tool=` 深链。
2. 同一业务域的二级导航必须只有一个来源，不能侧边栏一套、页面横向一套。
3. 页面内 tab 只表达同一对象的不同状态，不表达跨业务入口。
4. 旧路由只做兼容，不参与选中态、面包屑和推荐入口。
5. 说明页不作为二级导航项。

## 9. P0/P1/P2 落地顺序

### P0：先止血

目标：小白不再点进空壳页、旧路径、建设中能力。

- 从可见导航移除说明页、建设中模板、旧别名入口。
- 统一任务中心命名。
- 把 `/workbench/*`、`/interaction/*`、`/materials`、`/topics` 的按钮统一改到规范入口。
- 修复明显误跳：风控运行检查、成员权限账号设备、评论洞察规则入口。
- 所有空状态补一个下一步主按钮。

### P1：重做 4 个最复杂页面

目标：每页一个主任务。

- `/solutions` 改为任务模板启动器。
- `/distribution` 改为发布任务向导。
- `/tasks/evidence` 改为按任务聚合的操作凭证。
- `/materials` 改为选择素材，管理能力后置。

### P2：梳理业务链

目标：用户从一个任务自然走到下一步。

- 固定内容链和客户链。
- 结果页内提供下一步动作，不再让用户自己找模块。
- 任务历史支持“回到真实来源”，不要只回到泛化页面。

### P3：专家模式

目标：保留复杂能力，但不干扰小白。

- 专家模式显示完整系统设置、日志、调试、JSON、风控、连接器。
- 小白模式默认隐藏这些入口。
- 同一页面通过“高级”抽屉展开，不另开说明页。

## 10. 验收标准

第一轮完成后，用这 8 条验收：

1. 左侧可见入口不超过 6 个。
2. 没有可见导航直接跳到建设中能力。
3. 旧路由打开不再出现“推荐入口建议”干扰。
4. 每个业务页首屏只有一个主按钮。
5. 每个空状态都有下一步按钮。
6. 发布、互动、删除、远程执行都统一进入“待我确认”。
7. 记录类页面只保留“任务历史”和“操作凭证”两个概念。
8. 新手从素材到发布，最多经过 5 步：选素材 -> 生成内容 -> 发布前检查 -> 待我确认 -> 操作凭证。

## 11. 需要注意的风险

- 不建议直接删除旧路由，先兼容跳转，避免外部链接和历史记录断裂。
- 不建议把所有复杂页面一次性重写，先改入口和命名，再改四个 P0 页面。
- 不建议把“AI 员工”作为第一阶段主包装。当前更急的是把页面逻辑和业务链顺清楚；人设包装可以第二阶段再上。
- 不建议用教程解决复杂度。真正的目标是“不看教程也能完成第一件事”。
