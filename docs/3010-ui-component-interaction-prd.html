用户任务与产品目标

这份 PRD 解决的是“用户不知道系统在做什么”以及“页面每次都重新发明交互”的问题。

用户价值

看得懂状态

等待、处理中、需要确认、失败、超时和完成必须可区分，不能只显示一个转圈。

业务价值

少走冤枉路

列表详情用 Drawer/Expandable Row，分析可以下钻，表单按 Stepper 推进，尽量保持上下文。

工程价值

一次定义，到处复用

每个 Profile 只定义一套行为合同，页面只接入业务数据，不再复制弹窗、加载和错误状态。

范围与非目标

使用附件内容优化交互，不借机改产品导航或下架既有功能。

本期范围
  • 统一 7 类交互的触发、反馈、关闭、错误和完成状态。
  • 为 211 个前端路由绑定主行为 Profile。
  • 分别定义桌面端和移动端的交互替代。
  • 建立 P0/P1/P2 实施顺序和验收口径。
明确不做
  • 不复制演示 HTML 的紫色/橙色主题。
  • 不为了动画而动画，不使用假百分比。
  • 不删除或隐藏现有业务功能。
  • 不在本文件中宣称代码已经完成验收。

桌面端 / 移动端

同一个业务能力，不是把桌面布局缩小，而是根据设备改变交互入口。

桌面端

保留上下文，提升扫描效率

  • 沿用现有 Sidebar 和场景路由。
  • 高密度表格用 Expandable Row + Drawer。
  • 图表优先启用 Crosshair、Tooltip、Legend Filter、Drill Down。
  • 拖拽显示占位、可放置/禁止状态和服务端失败回滚。
  • Modal/Drawer 统一焦点陷阱、Esc 和焦点返回。
移动端

拇指可达，操作不依赖 Hover

  • 保留今天、内容、互动、线索、客户 5 项 Bottom Navigation。
  • Drawer 改为半屏/全屏 Bottom Sheet，保留拖拽条和关闭入口。
  • 图表用点击数据点、日期范围按钮和可滚动明细替代 Hover/滚轮。
  • 拖拽排序同时提供长按拖动和上移/下移按钮。
  • 生成、发布、群发按钮满足 44px 触控区，状态变化不跳布局。

实施排期

先修复反馈可靠性，再提升核心业务效率，最后补学习成本和细节。

P0 · 可靠性

先让状态真实

  • Overlay、Loading、错误/超时/重试统一。
  • 发布、群发、外部触达、权限和删除接入风险确认。
  • Agent/本地引擎/任务/证据明确生命周期。
  • 首屏列表补 Skeleton，移除空白等待。
P1 · 业务效率

再让流程顺手

  • 获客和情报图表联动、下钻。
  • 工作流/分发拖拽占位、跨列和失败回滚。
  • CRM/互动列表详情 Drawer、Expandable Row、Load More。
  • 内容生成支持 Drop Zone、Button Loading 和重试。
P2 · 学习成本

最后让产品会教

  • Product Tour、Coach Mark、Hotspot、Spotlight。
  • Checklist、Context Hint 版本化和埋点。
  • 知识库/后台 Tree View、Accordion、Collapse。
  • 案例、媒体、省钱页面渐进展开。

页面交互任务模板
页面：/growth/leads
Profile：P01
组件：Expandable Row + Drawer + Skeleton + Pagination
触发：点击线索行展开摘要；点击“查看详情”从右侧打开 Drawer
联动：筛选、分页、汇总数字和图表保持同一查询条件
状态：加载保留表格骨架；失败显示重试；关闭 Drawer 后焦点和滚动位置回到原处
设备：桌面右侧 Drawer；移动端半屏 Bottom Sheet
验收：不丢筛选、不跳滚动、Esc/返回键可关闭、键盘可操作、支持 reduced-motion
