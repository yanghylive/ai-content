Technical Design · Agent Cockpit · 2026-06-08

Agent 操作驾驶台技术设计

本文定义前端组件、状态模型、数据流、接口兼容、渲染安全和迁移方案。返回 立项书目录。

1. 架构原则

  • 复用现有 localEngineApi、AgentSession、Confirmation、Evidence，不重建本地引擎。
  • 驾驶台是当前任务工作区，不拥有商业真相；发布、互动、文件修改仍由原业务模块和本地引擎执行。
  • Agent 生成 UI 只能输出 Surface JSON，前端用白名单组件渲染。
  • 旧版 AgentConsolePage 行为必须兼容，便于逐步切换。

2. 组件拆分

组件职责依赖
AgentCockpitPage页面容器，管理 Chat + Persistent Canvas 布局、当前会话、当前草稿和当前 Surface。Next page、localEngineApi
AgentConversationPanelChat 输入、消息、文件附件、普通回复。AgentIntentRouter
AgentTaskDraftPanel任务草稿表单，支持字段编辑和预检补齐。TaskDraft ViewModel
AgentCockpitCanvas右侧当前任务工作区，渲染任务草稿、操作预览、确认卡、证据卡和交付物。AgentSessionProjection、Surface state
KaypalAgentSurfaceRenderer渲染 task_draft、approval_panel、evidence_list 等白名单面板。Surface Catalog
AgentSessionTimeline统一事件时间线，复用现有 EventTimeline 逻辑。AgentSession.events
AgentSafetyGatePanel只在当前任务需要时展示 blocker、risk policy、confirmation。ActionBlocker、Confirmation

3. 状态模型

type AgentCockpitState = {
  activeConversationId: string | null;
  activeSessionId: string | null;
  mode: "chat" | "draft" | "running" | "waiting_confirmation" | "completed" | "failed";
  draft: AgentTaskDraft | null;
  session: AgentSession | null;
  confirmations: AgentConfirmation[];
  surfaces: KaypalAgentSurface[];
  activeSurfaceId: string | null;
  artifacts: AgentDeliverable[];
  health: LocalEngineHealth | null;
};

状态来源分三类：用户输入产生 draft，local-engine 产生当前 session/events/evidence，confirmations 产生当前任务审批卡。health/browserStatus 只作为预检信号，不渲染为全局仪表盘。

4. 数据流

用户输入
  -> AgentIntentRouter
  -> 普通 Chat 回复 或 AgentTaskDraft
  -> preflight(draft, health, accounts, permissions)
  -> ready_to_run
  -> localEngineApi.createAgentSession(...)
  -> poll/refresh AgentSession
  -> project current task into cockpit canvas
  -> confirmations/evidence/deliverables

5. 兼容策略

现有能力保留方式新增方式
指令创建任务继续支持 instruction、executionScope、targetApp。增加 taskDraft 可选字段，不传时使用旧逻辑。
BlockerList保留原阻断文案。增加 resolutionActions，渲染补齐按钮。
SessionCard/EventTimeline保留在任务记录页。Canvas 只投影当前任务的关键步骤和产物。
ConfirmationsPage继续作为独立页面。Canvas 只在当前任务需要决策时渲染确认卡。
ArtifactsPage继续作为全集合页。Canvas 只展示当前任务产物和证据卡。

6. 最小开发顺序

  1. 抽出 AgentSessionProjection，把当前 session/events/evidence 投影成当前任务工作区数据。
  2. 新增 AgentTaskDraft 类型和前端预检逻辑。
  3. 实现三栏 AgentCockpitPage，先复用旧 createAgentSession。
  4. 实现 KaypalAgentSurfaceRenderer 和 3 个基础 Surface。
  5. 接入当前任务 confirmation/evidence Surface，不做全局数量看板。
  6. 补浏览器验收和旧流程兼容测试。
首期允许规则解析优先，LLM 任务草稿生成可以放在 P1.5；不要因为模型链路阻塞驾驶台骨架。
