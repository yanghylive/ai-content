# Xiaohongshu 视觉素材

## 目的

将已批准的笔记角度、已核实的事实和合法的素材来源转化为成品 Xiaohongshu 平面视觉素材。负责封面、首图、轮播卡片、解释性图表、证据截图处理、导出包和视觉素材交接；当生产工具和输入素材可用时，不要止步于图片简报。

将事实证据与生成的构思图像保持视觉上的明确区分。切勿暗示某个生成的场景、重构的界面、说明性图表或模拟截图是观察到的证据。

## 触发条件

以下情况使用此 skill：

- Xiaohongshu 笔记的封面或首图。
- 具有连贯阅读顺序的多卡片轮播。
- 对比图、流程图、架构图、时间线、标注截图或其他解释性图形。
- 证据截图列表、编辑计划、引文处理或溯源审查。
- 品牌一致的视觉变体或用于发布的完整文件包。
- 视觉质量检查，包括文字准确性、裁剪适应性、移动端可读性、版权、隐私或证据完整性。

对于自定义编码的交互式演示、网页、组件或可复用的视觉应用程序，不要触发此 skill。将这些实现工作移交给 FrontDeveloper，同时保留 Xiaohongshu 文案、受众意图和验收约束。

## 必需输入

- 笔记目标、目标受众、已批准的切入角度和预期的读者行动。
- 定稿或版本化文案、事实主张、来源以及任何强制限定词。
- 品牌指导原则：logo 规则、颜色、排版、语气、禁止的处理方式以及参考示例（若有）。
- 提供的素材路径及其来源、所有权、许可、同意声明和复用限制。
- 每张图片的目标位置：封面、首图、轮播位置、解释、证据或备选变体。
- 当前平台和用户在确切发布界面的约束，包括当前接受的的文件类型、尺寸或宽高比、数量、裁剪行为和大小限制。

执行前，从用户的简报、当前的权威平台来源或观察到的当前发布界面验证并记录当前约束。不要复用记忆中的或固定的 Xiaohongshu 尺寸。如果无法确认约束条件，创建适应性布局方案或可编辑源文件，并将最终导出尺寸标注为"待确认"。

## 工作流程

### 1. 锁定视觉合约

1. 将每个视觉素材映射到一个读者任务和一个笔记章节。
2. 将定稿文案与草稿文案分开；冻结用于视觉素材生产的文本版本。
3. 记录当前平台约束及其来源或确认状态。
4. 在生产变体之前定义品牌标识符和所需的视觉层次结构。

### 2. 构建素材和证据台账

将每个输入分类为以下之一：

- `EVIDENCE`：支持某个主张的真实截图、照片、文档摘录或捕获结果。
- `USER_PROVIDED`：由用户提供，但所有权或权限仍需记录。
- `LICENSED`：可根据已知许可或授权复用，归属要求已记录。
- `GENERATED_CONCEPT`：AI 生成或重构的图像，仅用作插图说明。
- `UNVERIFIED`：溯源、授权或事实状态未解决，因此不能进入发布就绪集。

对于每个证据截图，记录：

- 来源 URL、应用程序、文档、账户或本地文件。
- 与主张相关的捕获或访问时间。
- 它所支持的确切主张以及来源中可见的任何限制或限定词。
- 是否被裁剪、标注或编辑；如有原始版本请保留。
- 版权、授权、个人数据暴露、账户标识符和所需编辑内容。
- 防止裁剪改变含义的说明文字或来源标签。

永远不要将`GENERATED_CONCEPT`项目放入证据槽位。在合理读者可能误认为证据、真实界面、真实人物或真实结果的生成或重构图像旁标注说明。

### 3. 设计序列

- **封面：** 用足够的对比度和层次结构表达一个真实的承诺，以经受缩小的移动端预览；不要使用笔记无法兑现的噱头。
- **首图：** 建立上下文、价值或有用的摘要，不要假设封面裁剪保持不变。
- **轮播卡片：** 每张卡片一个主要观点，保持编号或递进关系，序列在隐藏过渡的情况下也能被理解。
- **解释性图表：** 保留因果方向、单位、标签、图例和不确定性；在简化含义之前先简化装饰。
- **证据卡片：** 保持来源身份、相关的时间戳或新鲜度、限定词和编辑内容可读；区分标注内容与原始内容。

### 4. 生产视觉文件

1. 使用本地或连接的最佳可用栅格、矢量、排版、截图或图像生成工具。
2. 当工具支持时保留可编辑源文件，仅在确认当前目标约束后导出。
3. 一致地应用品牌颜色、排版、间距、插图风格、logo 规则和披露处理。
4. 从冻结的文案来源复制文本；不要凭记忆重新输入关键名称、数字、命令、日期或主张。
5. 除非用户明确要求其他合法用途，否则仅将生成的图像用于概念或装饰；绝不生成虚假证据。
6. 当当前 runtime 缺少合适的图像生成器但 Codex 作为独立任务界面可用时，在当前运行中为`codex-visual-production`编写 v1 请求，并在`pending_codex`停止。不要请求或编造 OpenAI API 密钥，也不要将异步交接描述为 MCP 或 API 调用。

### 5. 运行视觉质量检查

检查每个最终候选文件：

- 精确的拼写、标点、名称、数字、日期、单位、代码、URL、来源标签和主张限定词。
- 在缩小的移动端预览下的可读性，而不仅仅是在创作规模下。
- 在当前观察到的裁剪行为下的安全层次结构；将核心含义远离不确定的裁剪边缘。
- 对比度、信息密度、卡片间一致性和清晰的阅读顺序。
- 颜色、字体、logo 使用、摄影、插图和披露标签的品牌一致性。
- 版权、许可、归属、肖像权、隐私、个人数据、机密信息和截图权限。
- 真实证据、标注、模型和生成概念之间的清晰分离。
- 文件完整性、可预测的命名、正确的排序以及发布就绪目录中无过时变体。

如果视觉素材无法在逼真的移动端规模或当前裁剪行为下进行检查，将该检查标记为待定，而非声称已通过。

### 6. 打包和交接

创建至少包含以下内容的清单：

| 字段 | 含义 |
|-------|---------|
| `id` | 稳定的视觉标识符和轮播顺序。 |
| `path` | 确切的最终文件路径；提供可编辑源文件路径（若有）。 |
| `role` | 封面、首图、轮播卡片、解释、证据或备选。 |
| `target_constraint` | 当前已验证的位置、格式、尺寸或比例及裁剪说明；绝非记忆中的默认值。 |
| `copy_version` | 文件中使用的冻结文本版本。 |
| `asset_class` | 证据、用户提供、许可、生成概念或未解决。 |
| `source_rights` | 来源、许可或授权、归属、隐私和编辑状态。 |
| `qa_status` | 文本、移动端、裁剪、品牌、证据、版权和文件检查。 |
| `publish_status` | 就绪、阻塞、备选或排除，附原因。 |

将最终有序路径、清单、冻结文案、证据台账、未解决风险、当前约束来源和审批状态移交给`publishing-checklist`。不要因为文件就绪就声称可以发布。

## 输出

- 当合适的生产工具和输入素材可用时，成品封面、首图、轮播、解释性或证据视觉文件。
- 当所选工具支持时，可编辑的源文件或可复现的说明。
- 具有确切路径和顺序的视觉序列图和文件清单。
- 证据截图清单和素材溯源台账。
- 涵盖文本、品牌、裁剪、移动端可读性、证据完整性、版权、隐私和剩余阻塞项的质量检查报告。
- 用于`publishing-checklist`的发布前交接包。

如果生产工具或必需素材不可用，返回可执行的视觉规格和阻塞项清单。不要将简报、提示或未检查的占位符描述为成品视觉素材。

## 审批门槛

- 本地视觉草图、生成、编辑、检查和导出本身并不授权账户或远程写入。
- 在进行任何`xhs post`或其他账户写入操作之前，需要用户对确切的顺序图片路径、标题、正文、话题、隐私状态、目标账户和命令的明确审批。
- 在进行任何 JPage 上传、覆盖、重命名、删除、可见性更改、模板实例化或远程 skill 同步之前，需要用户对确切的 base、源路径、目标文件或模板 ID、可见性、覆盖行为和命令的明确审批。
- 如果视觉素材、有效载荷、目标、可见性状态或命令在审批后发生变化，重新确认审批。
- 永远不要在视觉素材或跟踪清单中放置密钥、私人令牌、隐藏的个人数据或未批准的账户标识符。

## 故障处理

- 如果当前平台约束不可用，保持设计适应性，记录缺失的确认，并在最终尺寸特定导出前停止。
- 如果文本未定稿，创建明确标记的草稿布局并阻止发布就绪状态。
- 如果溯源、授权、同意或隐私未解决，从就绪集中排除资产并确定合法的替代方案。
- 如果证据在裁剪或编辑后无法读取，使用不同的证据处理方式；绝不要以改变含义的方式放大或重建它。
- 如果生成或编辑工具失败，保留源输入、命令或提示以及中间输出；报告确切的失败并使用安全的替代工具或生产简报。
- 如果账户或 JPage 状态在写入失败后不确定，在重试前验证远程状态。

- 仅将自定义编码的交互式演示、网页、组件或可复用的视觉工具移交给 FrontDeveloper。包括已批准的文案、当前目标约束、品牌规则、证据台账、交互行为和验收检查。
