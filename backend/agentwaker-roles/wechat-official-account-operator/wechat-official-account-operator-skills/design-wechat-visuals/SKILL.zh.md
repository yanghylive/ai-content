# 设计 WeChat 视觉素材

## 目的

将已批准的 WeChat 文章转化为一套连贯的、高质量成品视觉文件，用于解释内容、保存证据并符合账号品牌调性。brief、prompt 或缺图清单不算完成。不要创建账号草稿、上传素材或暴露预览链接。

## 必要输入

- 已批准的主题、大纲或文章草稿。
- 选定的编辑分类及其合同（来自 `../plan-tech-series/references/editorial-categories.md`）。
- 稳定的文章 slug 和 Markdown、清单及后续预览 HTML 共用的修订版本。
- 读者承诺以及视觉素材必须阐明的声明。
- 可用的截图、图表、架构图、Logo 及其权限状态。
- 后端显示需要封面时当前的 WeChat 封面裁剪方式。
- 任何明确的预算、图片数量、文本或视觉约束。
- 本地文章包目录，用于存放最终素材和清单。

## 工作流程

1. 阅读 `../plan-tech-series/references/editorial-categories.md` 并加载选定的分类合同。阅读 `references/brand-system.md` 并在选择封面或正文视觉路线前将包绑定到 `green-black-white-tech`。对于 `architecture-map`，在绘制任何内容前还要阅读 `references/architecture-infographic-system.md`。
2. 阅读 `references/visual-quality-gate.md` 和 `references/visual-brief-template.md`。仅将 `references/visual-manifest.example.json` 作为紧凑的 schema 示例。
3. 扫描每个 H2 章节。记录读者是否需要截图、架构或工作流图、对比图、图表、概念插图，或有明确理由的纯文字章节。
4. 应用 `visual-quality-gate.md` 中的文章类型下限。封面和装饰素材不计入，两个连续的纯文字 H2 章节需要获得批准的豁免。
5. 产品界面、命令、错误和实测结果优先使用真实截图；架构和流程优先使用原创图表；数据优先使用来源绑定的图表；封面或抽象解释优先使用生成的概念图。绝不生成看起来像证据的 UI、终端输出、图表、Logo 或基准测试。
6. 在绿-黑-白体系中选择一种分类处理方案。让黑色和白色承载构图，绿色仅用于活跃路径、已验证状态、选中区域和编辑判断。优先使用确定性图表和真实证据，而非生成的概念场景。
7. 生成实际的最终文件。除非用户已选定精确的参考方向，否则至少生成两种封面构图；对于其他概念素材，迭代直到一张通过关卡。选择最强候选，移除意外或错误的文本，并确定性添加必要标签。对于图表和图表，保留可编辑源文件，并将审核后的可发布图片导出为 PNG。
   - 对于 `architecture-map`，使用结构化数据加确定性 SVG、HTML/CSS、Mermaid 衍生 SVG、Graphviz、Figma 组件或其他代码原生矢量方案。先制作完整的架构概览。赋予其稳定的编号区域、名称、颜色、箭头、边界、依赖关系、存储位置和图例。从该概览通过高亮或缩放相关区域推导每个本地架构或工作流说明；保留概览的 ID、名称、颜色和关系语义。在清单中记录概览和详情绑定。不要使用 ImageGen 生成概览或其详情图。
   - 对于 `open-source-recommendation`，优先使用工作流或能力地图、最小用例的真实证据，以及同任务对比或决策图。不要用装饰性启动图替代采用证据。
   - 当当前 runtime 缺少合适的图片生成器但 Codex 作为独立任务界面可用时，在当前运行中为 `codex-visual-production` 撰写 v1 请求并停止在 `pending_codex`。不要请求或自创 OpenAI API key，也不要将异步交接描述为 MCP 或 API 调用。
8. 在原始尺寸、文章宽度、当前后端裁剪和窄幅手机缩略图下检查每个最终文件。检查事实准确性、精确文本、AI 痕迹、构图、对比度、品牌一致性、裁剪安全性、水印、权限、隐私和证据状态。拒绝通用 AI 母题、米色产品摆拍、三维纸或玩具场景、装饰性隐喻、卡片堆叠，以及任何无法解释文章的素材。
9. 创建 `visual-manifest.json`，将每次审核绑定到最终文件 SHA-256，并记录 alt 文本、`▲` 标题、放置位置、尺寸、需求、硬检查结果和质量分数。仅当每个所需素材都是 `approved` 且没有占位符时，才将 `asset_gate=pass` 标记为完成。
10. 将成品素材、人类可读的 brief 和清单交接给 `format-wechat-article`。该 skill 必须在 `jpage-pre-draft-preview` 可以上传或展示任何内容前构建并验证集成页面。

## 输出

- 仅限 WeChat 的视觉方向和封面处理方案。
- 最终封面和所有必需的正文图片文件。
- 人类可读的视觉 brief 加绑定到文章修订版的机器可读 `visual-manifest.json`。
- 适用时的可编辑图表或图表源文件，以及生成或捕获来源。
- 最终素材路径、哈希值、尺寸、alt 文本、标题、权限说明、质量分数和裁剪就绪证据。
- `asset_gate=pass`，或明确列出缺失或被拒素材的阻止结果。阻止结果无法继续预览。

## 审批门控

- 本地视觉 brief 或清单无需审批。
- 当成本未预先约定时，在批量付费或异常大规模生成前确认。
- 在向任何外部生成服务发送未发布文本、私人截图、源代码或内部数据前确认。
- 将生成的或捕获的素材上传到 WeChat 视为由发布 skill 拥有的单独写入操作。

## 失败处理

- 如果当前封面裁剪方式未知，生成裁剪安全的母版并标记需要后端验证。
- 如果截图包含私人数据，在本地删除或用明确标注的示意图替换。
- 如果生成的文本不准确，移除它并在文章布局中添加标签，而非反复重新生成装饰性文本。
- 如果素材缺少明确的权限，省略它或创建原创的解释性替代品。
- 如果自适应视觉下限无法用有用素材满足，停止并提交有理由的差距报告或获取明确的密度豁免；绝不以装饰填充差距。
- 如果任何所需素材未通过事实、技术、移动端、权限、隐私或质量审核，重新生成、重新捕获或重新设计它，并保持 `asset_gate=fail`。

## 交接规则

- 始终将最终本地素材和当前修订版清单交接给 `format-wechat-article`；视觉生产对于成品文章不再是可选分支。
- 将自定义交互图表或代码原生可视化交接给 FrontDeveloper。
- 将账号上传、草稿变更和发布交接给相关的 WeChat 发布 skill。
- 不要在本 skill 中创建 Xiaohongshu 卡片、笔记、封面、发布任务或跨平台衍生品。

## 触发条件

当请求匹配此处描述的工作流程且保持在 WeChat 订阅号运营者边界内时使用本 skill。
