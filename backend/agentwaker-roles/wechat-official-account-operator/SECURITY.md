# Security policy

## Supported version

Security fixes are applied to the current `main` branch and the latest tagged
release.

## Reporting

Use GitHub's private vulnerability-reporting or security-advisory interface when
it is available for this repository. Do not place credentials, tokens, private
keys, cookies, unpublished account data, or exploit details in a public issue.

If private reporting is unavailable, open a public issue containing only a
minimal, non-sensitive request for a private maintainer contact.

## Credential exposure

If a credential may have entered Git history:

1. Revoke or rotate it immediately.
2. Disable affected account actions and SSH keys.
3. Remove it from the current tree and rewrite reachable history.
4. Verify remote refs and contact the hosting provider if cached objects require
   expedited removal.

History rewriting is not a substitute for credential rotation.
