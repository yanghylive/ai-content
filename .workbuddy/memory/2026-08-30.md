**大王澄清「技术底座」口径（2026-08-30）**：底座 = **用户、订阅、积分、治理** 四条核心业务链路；**展示站（官网前端）不属于底座，可以动**。

**核心链路影响评估结论（A′ 方案，全部零改动）**：
- 用户（认证/OIDC）：零改动，落地页不调用户接口
- 订阅：零改动，CTA 只跳已有 /pricing
- 积分：零改动，无计费/扣减路径
- 治理：零改动，不碰审批/预算/边界规则

**唯一交集（已实测排除风险）**：落地页 `FrontdoorViewTracker` 埋点 → `POST /api/telemetry/task-funnel`。
- 游客：`getCurrentUser()` 为 null → **204 静默丢弃，不写 audit log、不报 401**
- 已登录：写一条 `resource: 'task_funnel'` audit log（落地页原有设计，04-22 前就在跑，不改治理规则）
- 网关侧配置 `auth: 'optional'`（routes-config.ts:722），按声明顺序优先于 requiredApiPrefixes
- 线上实测对照：`POST /api/telemetry/task-funnel` → 204；`GET /api/subscription` → 401（证明 required 策略生效）
- 不想写 audit log 的话，落地页不渲染 FrontdoorViewTracker 即可（可选，不阻塞）

**最终推荐方案 A′（页面内按域名分流）**：只改 `src/app/[locale]/page.tsx` 一个业务页面文件，在页面内 `await headers()` 读 host，命中 `vip.kaypal.cn` 则 redirect 到 `/dashboard/apps`，否则渲染 `PublicHomeLanding`。middleware 一行不动，host 取值顺序照抄 middleware 的 `getRequestHost()`（x-forwarded-host → host）。兜底：host 读不到时渲染官网（宁可漏跳 vip，也不能把官网访客送进登录页）。

**关键技术点（已实测确认）**：
- 项目 next@^15.5.14 + react 18.3，**`headers()` 在 Next 15 是异步 API，必须 await**（项目内 `sitemap.ts` 已有 `await headers()` 先例）。别写成同步。
- 性能无回退：线上 `/zh-CN` 响应头实测 `cache-control: private, no-cache, no-store, max-age=0`，无 `x-nextjs-cache`/`age` 头 → **该路由已是逐请求动态渲染**（middleware 每次写 NEXT_LOCALE 等 4 个 cookie 导致路由被标 dynamic）。加 headers() 不改变渲染模式。

**关键风险**：已登录用户访问 kaypal.cn 会从"直接进工作台"变成"看官网落地页"（落地页无登录态判断，CTA 只有登录/免费试用）。

**www.kaypal.cn**：SSL 证书域名不匹配，访问失败。大王决定「直接砍掉 www」，建议去域名控制台删 www 的 A/CNAME 解析（比挂证书错误页干净）。

**二狗给的建议（4 项）**：① 选 A′ ② 「进入工作台」入口这次不做（已查证已登录用户点「登录」→ LoginPage 检测 user?.id → redirect 回 dashboard，resolveLoginReturnTarget 默认 fallback 即 dashboard 入口，路径通）③ 埋点保持开启（游客 204 零成本，官网刚恢复需要漏斗数据）④ www 删 DNS。
