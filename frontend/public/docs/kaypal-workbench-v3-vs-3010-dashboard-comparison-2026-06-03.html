KaypalAI 内容创作平台 3010 总览页 vs Kaypal Workbench V3 首页
Page Comparison
目标说明

对比的不是 token，是两个真实首页该怎么对齐。

Kaypal Workbench V3 的首页是“任务发起入口”：用户输入需求，选择项目类型，进入最近项目和插件市场。 3010 的首页是“内容运营总览”：看素材、草稿、发布、客户互动和执行日志。两者不能完全长一样， 但 3010 应该吸收 Workbench V3 的入口清晰度、层级克制和统一组件规则。

对比对象 http://127.0.0.1:3010/ 的总览页，对比 http://127.0.0.1:49648/ 的 Kaypal Workbench 首页。
当前注意 3010 未登录时会跳登录页；真正总览页内容来自 frontend/src/app/(dashboard)/page.tsx。
结论 3010 不应变成 Workbench 的 prompt 首页；它要保留运营仪表盘定位，但视觉组织要向 Workbench V3 收口。

一、页面定位对比

先判断两个页面分别解决什么问题，避免把 3010 改成另一个产品。

维度 Kaypal Workbench V3 3010 总览页 处理方式
用户目的 我要让 AI 帮我设计、生成、修改一个项目。 我要看今天内容运营跑得怎么样，下一步该处理什么。 定位不同
第一屏核心 大输入框、项目类型 tab、最近项目。 KPI、趋势图、GEO 联动、待发布草稿、系统日志。 保留业务
主动作 输入需求并运行。 刷新数据、去执行、去发布、查看记录。 动作收口
信息密度 首页偏入口，展示密度中等。 后台总览，信息密度应该更高。 不降密度
视觉表达 浅色、轻量、创作入口感。 暗色、监控、运营后台感。 只学结构

二、3010 应该向 Workbench V3 学什么

这些是可以直接吸收的 UI 逻辑，不会破坏 3010 的业务定位。

入口清晰

第一屏要让用户知道下一步

  • Workbench 首页的“你想设计什么”很明确。
  • 3010 总览页也要明确：待处理、去发布、去执行、看日志。
  • KPI 卡片不能只是数字，要能指向操作。
层级克制

减少装饰，强化结构

  • Workbench 的 tab、最近项目、插件列表层级清楚。
  • 3010 的图表、任务、日志也要统一标题、按钮和间距。
  • 不要每块卡片都做不同风格。
统一组件

同类内容用同类组件

  • Workbench 的列表项是一套重复结构。
  • 3010 的草稿、GEO 任务、日志、记录也要形成固定列表模型。
  • 按钮、标签、状态、图标必须统一。

三、3010 不应该照搬什么

这几类照搬会把内容运营后台改偏。

Workbench 元素 为什么不照搬 3010 应该怎么做 结论
大 prompt 输入框 Workbench 是生成入口；3010 是运营总览，不是聊天/设计生成首页。 保留数据总览；如果要 AI 指令，放到智能任务或独立入口。 不照搬
项目类型 tab 原型、实时制品、幻灯片、图片、视频是 Open Design 的产物分类。 3010 用内容生产、发布中心、客户互动、系统设置这些业务分组。 不照搬
Community 插件市场 3010 用户不是来选插件的，是来运营内容和执行平台动作的。 可以保留能力中心/系统配置，但不放在总览第一屏。 不照搬
浅色主视觉 当前 3010 V3 已经是暗色后台，用户也要求不要乱改颜色。 保持黑底深灰蓝色，只吸收间距、组件、层级逻辑。 保留暗色

四、3010 总览页具体调整建议

按优先级从“最像 V3 工作台逻辑”到“后续细节”。

区域 现状 建议 优先级
页面头部 标题是“AI 工作台与监控中心”，右侧刷新数据。 保留。可补一行短说明：今日内容生产、发布和互动执行状态。 P1
KPI 卡片 今日素材、待发布、风向词、成片统计。 每张卡增加明确跳转：去采集、去文章库、去选题、去发布记录。 P0
趋势图 素材采集趋势、文章创作趋势。 统一图表高度和空状态；无数据时不要大面积空黑。 P0
GEO 联动 有 GEO 联动任务卡，可能为空。 保留，但空状态要写“没有待执行任务”，并给“去智能任务”入口。 P1
待发布草稿 展示最新待发布草稿。 这是 3010 的核心转化区，要比日志更靠前、更明确。 P0
系统日志 展示实时系统日志。 保留在下半区；只显示用户能懂的状态，内部错误去运行检查页。 P1
导航 3010 左侧导航是完整业务模块。 不改成 Workbench 的项目/自动化/设计体系；保持 3010 业务导航。 P0

最终判断

3010 首页不应该变成 Kaypal Workbench 的“你想设计什么”入口。 正确方向是：保留 3010 的运营仪表盘和左侧业务导航，把 Workbench V3 的“入口明确、组件统一、层级克制、重复结构稳定”拿过来。

保留 3010
  • AI 工作台与监控中心
  • KPI、趋势图、待发布草稿、GEO 联动、系统日志
  • 内容生产、发布中心、客户互动的业务导航
吸收 Workbench V3
  • 第一屏任务入口更清楚
  • 列表/卡片/按钮/状态统一
  • 减少无意义装饰，所有模块都指向下一步动作

对比依据：Kaypal Workbench 页面 http://127.0.0.1:49648/；3010 总览页代码 frontend/src/app/(dashboard)/page.tsx；当前 3010 未登录时会跳转登录页。
